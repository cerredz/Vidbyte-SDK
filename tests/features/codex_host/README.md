# CodexHost feature tests

## Folder Description / Intent

This folder checks the public promise of `CodexHost` in `vidbyte.harnesses.native.codex`: fifty-three small async functions over one `codex app-server` process, an optional `approval_handler` that answers Codex's approval and user-input requests, the six module functions that open a host for one call, and `CodexHostTools`, which gives forty-two of the functions one agent tool each; `delete_codex_thread`, the local `forget_codex_turns` and the nine developer-only functions of codex-host-first-class INV-42 have none. The tests drive a real `CodexHost` against an in-memory app-server. The real openai-codex `CodexClient` runs over a fake pipe, so its reader thread, message router, retry helper and goal routing all run unmocked. Only three things are replaced: the subprocess, at the spec's test seam `vidbyte.harnesses.native.codex.connection.CodexClient`, plus `shutil.which` and `sys.platform`. The worktree tests also patch `Path.home` and run the real git on temporary repositories, with the user's git config shut out.

The implementation belongs in `vidbyte/harnesses/native/codex/` (the host, connection, wire, turns, preflight, errors and module functions), `vidbyte/lib/dataclasses/codex_host.py` and `codex_host_inputs.py`, `vidbyte/lib/enums/codex.py`, `vidbyte/lib/constants/codex.py` and `codex_host.py`, `vidbyte/tools/builtins/codex/` and `vidbyte/tools/toolsets/codex.py`. The contract comes from `docs/spec/codex-host/spec.md`, the twelve thread helpers' contract from `docs/spec/codex-host-thread-helpers/spec.md`, the hardening slice's from `docs/spec/codex-host-hardening/spec.md`, whose test plan is `docs/spec/codex-host-hardening/test-plan.md`, and the first-class-features slice's from `docs/spec/codex-host-first-class/spec.md`, whose test plan is `docs/spec/codex-host-first-class/test-plan.md`.

## Non-Goals

- Do not run a paid `codex` turn, and do not start a real app-server in the default run. A live turn spends the user's Codex plan (NG-13), so the live half of AC-1 is manual QA. The one exception is `test_codex_host_live_smoke.py` (codex-host-hardening X9, D-28, AC-35): it runs only when `VIDBYTE_CODEX_LIVE_TESTS=1`, the `codex` extra is installed and `codex` is on PATH, and then it calls only non-spending reads and never prints an account field. Never add a spending call to it.
- Do not test `CodexHarnessAgent` here. `tests/test_codex_tools.py` and the other `tests/test_codex_*.py` modules own it, and they must keep passing unchanged (NG-5).
- Do not test controls the spec leaves out: MCP permission checks (Q-7), restricting thread tools to their own toolset (Q-8), or spending ceilings (Q-9).
- Do not mock above the seam. The records, the Codex translators, `UsageTracker`, `ToolExecutor`, `PermissionPolicy`, `Tools` and `McpStudioServer` all run for real.
