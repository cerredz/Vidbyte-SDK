# Jev agent

This package owns Vidbyte's opinionated Jev agent. Its dedicated runtime can run named Jev-backed preflights before the established linear model/tool loop.

- `settings.py` is the complete public configuration surface: `JevAgentSettings` for the main agent and its `JevSpecialist` candidates, and `JevRuntimeSettings` for Jev's decision model, preflight flags, continuation settings (`JevContinualSettings`: done checks, continuation gate, and limits), and tool-selector threshold.
- `agent.py` maps those settings into `BaseAgent` with the `jev` runtime type (`AgentRuntimeType.JEV`).
- `gate/` holds the gate for fixed-question presets. `JevPreflightGate` combines every enabled preset's questions into one Jev request, scores each preset with `DecisionModelHelper`, and its `pass_` match statement acts on the outcomes and returns whether the generative agent runs. When `JevAgentSettings.agents` is set, the same request carries one Choice question over the specialists, and the gate records the one Jev ranked first. `JevClarificationAgent` returns structured clarifying questions, each with a few recommended answers, when the request is unclear.
- `done/` holds the done checks: `JevRunState` writes the run state from the request before the main loop and runs every enabled check when the main agent tries to finish, and `JevHandoff` compiles the evidence those checks judge from the main agent's context window. REQUIRED_SEQUENCE adds request-derived stages and checks cited run events for stage presence and strict order before the run can finish.
- `continuation/` holds the continuations the runtime calls at every finish attempt: `JevContinuation` (`should_continue`, `continue_`), `JevDoneContinuation`, and `JevFreshContinuation`, which uses the same failed-check trigger and cap to run a fresh agent context before returning work to the main loop.
- `preflight.py` holds the tool selector (`JevPreflightTools`), which keeps its own path in the runtime.
- `brief/` holds the run brief, a structured, verified record of the main agent's current work kept between iterations for mid-run decisions: `JevRunBriefKeeper` decides when to refresh it from exact run facts (`JevRunFactsReader`), `JevRunBriefWriter` is the separate, tool-free agent that rewrites it from the newest numbered events (`JevRunBriefEvents`), and `JevRunBriefVerifier` keeps only quotes found in the events they cite. `JevRunBriefSettings` chooses the writer's model, which can be cheaper than the main agent's. 
- `compute/` holds `JevComputeController`, the mid-run compute checkpoint. Set `JevRuntimeSettings(compute=JevComputeSettings(brief=JevRunBriefSettings(model_name=...)))` to turn it on: `JevRuntime` calls the controller after every tool iteration that continues the main agent's run (through `AgentRuntime._after_tool_iteration`), and the controller keeps the run brief current and reports `agent.response.run_facts`, `run_brief`, and `run_brief_updates`. After each verified brief refresh it asks Jev which compute situation the run is in (`JevComputeSettings.situations`: REPEATING, EACH_OF_SEVERAL, SELF_CONTAINED_STEP, in priority order). Code picks each situation's subject from the brief and skips situations the brief cannot show; Jev answers four fixed sign questions per eligible situation (`vidbyte/lib/jev/compute/`), and a situation passes on its mean, veto, and gate. Decisions are reported on `agent.response.compute_decisions`. When REPEATING is recognized and the run-local budget allows (`max_moves`, `max_helpers`, `cooldown_iterations`), a fresh helper agent (a separate linear agent with the main agent's model, tools, and permissions and an empty history) takes the stuck problem, told which approaches already failed; its report is appended to the main loop and its work is recorded as done-check evidence. When EACH_OF_SEVERAL is recognized, each pending item of the group goes to its own helper, built from the verified brief and the agent's own quoted plan, run in parallel up to `max_parallel_helpers`; every item's report comes back in one message and items beyond the budget stay with the main agent. When SELF_CONTAINED_STEP is recognized, one fresh helper reuses the main agent's system prompt and receives the original request with the available JEV run state and verified mid-run brief as typed context; only its clipped report returns to the main loop. Each item and unchanged helper context is handed out at most once per run. Each move is reported on `agent.response.compute_moves`. Specialists and fresh continuations run without the checkpoint.
- `response.py` defines `JevResponse`, the only writer of the `JevAgentResponse` record exposed as `JevAgent.response`.
- `runtime.py` calls the gate before the inherited `AgentRuntime` loop and returns the gate's response when it closes, runs the chosen specialist's own agent when the gate chose one, and otherwise applies the tool selector when it is enabled; `RuntimeRegistry` resolves the `jev` runtime type to it.

`agent.py` builds the gate and the response writer at construction and passes them to the runtime. Question text lives in `vidbyte/lib/jev/`: `presets.py` (`JevPresets`) owns the flags a user can enable in `JevRuntimeSettings.preflight` and the questions each fixed-question flag asks, and `preflight/` holds one dataclass per question, the specialist question, and `JevPreflightRegistry`. The flag and question-key enums are in `vidbyte/lib/enums/jev.py`, and the records are in `vidbyte/lib/dataclasses/jev.py`.

Enable request clarity checks with `JevPreflightPreset.CLARITY`. When the request is unclear, the run stops before the generative agent starts, `agent.response.clarification` holds the questions and their recommended answers, and the reply content is those questions as a numbered list.

Enable tool selection with `JevPreflightPreset.TOOL_SELECTOR`. `tool_selector_threshold` defaults to `0.20` and accepts finite probabilities from `0.0` through `1.0` inclusive. If Jev is unavailable or returns incomplete answers, the run keeps the full configured tool catalog, and the reply metadata reports the selection under `jev_tool_selector`. After each run, `agent.response.results` holds one outcome per enabled fixed-question preset.

Hand whole tasks to specialists with `JevAgentSettings.agents`: each `JevSpecialist` pairs a title and a scope description with the `BaseAgent` that runs the task when Jev picks it. Jev may also pick `none`, and a missing or failed answer counts as `none`; either way the main agent runs. `agent.response.specialist` names the specialist that ran, and a chosen specialist runs through its own agent, so this agent's tool selector does not filter its tools.

Enable done checks with `JevRuntimeSettings(continual=JevContinualSettings(checks=...))`. `MULTI_PART` checks each request-defined deliverable; `TARGET_OUTCOME` requires direct evidence that a requested result reached its target; and `MOTIVATING_CASE` checks request-named unusual conditions in the permitted mode, not just ordinary flow or an easier near miss. `SCOPE_COVERAGE` records request-named groups that require a change for each member, gathers per-member work evidence, and preserves missing workspace listings as gaps; a bounded breadth review can upgrade a narrow label before work. CLAIMS and PROBLEMS_RESOLVED use evidence available only after work. `REPORT_ACTION_ALIGNMENT` compares explicit earlier plans with recorded execution and the final account, while respecting whether the user required the planned result. Every enabled check is judged in one request, and failures send the main agent back through the same loop up to `JevContinualSettings.max_continuations` (default `JEV_DONE_MAX_CONTINUATIONS`); unavailable checks fail open and the current answer stands at the cap. `agent.response.run_state`, `handoff`, `done`, and `continuations` report the outcome. The questions live in `vidbyte/lib/jev/done/`.

`INPUT_SET_COVERAGE` checks each explicitly bounded input target the request asks the agent to read, inspect, review, compare, or process. The handoff compiles tool-call evidence, and Jev judges engagement across the requested scope and depth; this check suits finite user-bounded targets, while open-ended or dynamically paginated collections need an exhaustion check. Enable it with `JevRuntimeSettings(continual=JevContinualSettings(checks=(JevDoneCheck.INPUT_SET_COVERAGE,)))`, then inspect `agent.response.done[JevDoneCheck.INPUT_SET_COVERAGE]` and the target entries in `agent.response.run_state.input_set_coverage` and `agent.response.handoff.input_set_coverage`.

`DISCOVERED_ITEM_COVERAGE` derives candidate collections from recorded tool outputs. Code preserves each bounded raw output and requires the handoff to account for every recorded source id; Jev then checks each source inventory and each discovered item's requested processing independently in the same decision batch. A source inventory gap sends the original output back with the omitted candidates to review.

With `JevDoneCheck.NEGATIVE_COVERAGE`, the run state lists targets the user explicitly asked to inspect. The handoff pairs each target with visible run evidence of inspection and any final-answer no-findings, all-clear, or explicitly incomplete report. The check sends a target back only when the answer reports it clear or incomplete without inspection evidence; a supported clean result passes and no finding is required.

With `JevDoneCheck.FAITHFUL_SCOPE`, `JevRunState` records one `hard_part` from the request before work begins. At each finish attempt, `JevHandoff` reports run evidence about that requirement and Jev checks whether the work met it without narrowing, mocking, skipping, hard-coding a substitute, or redefining it. A failed check sends the main agent back with the hard part in focus. Each such continuation receives the configured additional `faithful_scope_extra_iterations`, `faithful_scope_extra_tokens`, and `faithful_scope_extra_tool_calls` (defaults: 2, 16,000, and 4), added only to finite limits on the same loop. `agent.response.continuation_budget` records the cumulative extra limits granted. Missing run state, handoff evidence, or Jev answers fail open.

With `JevDoneCheck.SELF_REVIEW`, a tool-free `JevReviewer` examines the main agent's run before the handoff at each finish attempt and lists up to three objections, most serious first. The handoff reports evidence for exactly those objection ids, then Jev answers whether each is resolved and whether it is in scope. An objection clears when either confidence in resolution or confidence that it is out of scope reaches the configured threshold; a standing in-scope objection focuses the same-loop continuation. A failed reviewer or handoff fails open for this check while other enabled checks still run, and a valid review with no objections passes without a Jev question. `agent.response.review` holds the latest review.

Enable ordered-stage review with `JevContinualSettings(checks=(JevDoneCheck.REQUIRED_SEQUENCE,))`. The run-state writer derives stages only from exact source phrases in a request that explicitly requires an order. At each finish attempt, the handoff cites numbered run events; code checks that every stage has recorded work and that stage work happened in strict order. Jev separately recognizes whether the recorded work shows each stage's completion criterion and whether a dependent stage used its predecessor's output. A failed stage sends the main agent back into the same loop, within the configured continuation limit.

Set `JevContinualSettings(gate="fresh", checks=...)` to apply the same failed-check trigger through a clean agent context. That agent receives the original request, run state, and handoff, and its response is returned to the main loop; the default `gate="same_context"` keeps the established continuation path.

Do not add a generic `decisions` collection or runtime replacement option. Add named, validated settings for product capabilities and keep their internal questions and actions inside this package.

Add `JevDoneCheck.TARGET_OUTCOME` when the task asks for a result on a target beyond producing the answer or another requested output. The run-state records the requested outcome, actual target, scope, and completion criterion; at each finish attempt, the handoff separates observed proxy milestones from direct evidence about that target. Jev checks whether the evidence demonstrates the requested result on the actual target at the requested scope. Requests with no separate, well-defined target outcome produce no target-outcome items and pass this check without a Jev question. Enable it alongside other checks, for example `JevRuntimeSettings(continual=JevContinualSettings(checks=(JevDoneCheck.MULTI_PART, JevDoneCheck.TARGET_OUTCOME)))`.
With `JevDoneCheck.PROBLEMS_RESOLVED`, the handoff derives one item for every problem observed during that run and one required item for completion of the original request after repairs. Jev judges every item in the same combined request; a failed problem sends the main agent back to repair and revalidate it, then return to the original request and finish remaining work. The check is opt-in, runs in the same loop, respects the same continuation cap, and fails open when evidence or Jev is unavailable.
Enable done checks with `JevRuntimeSettings(continual=JevContinualSettings(checks=...))`. With `JevDoneCheck.MULTI_PART`, `JevRunState` lists the separate deliverables the request asks for, and each time the main agent tries to finish, `JevHandoff` compiles the evidence for each one and Jev judges, in one request holding every enabled check's questions, whether each was produced in full. With `JevDoneCheck.CAN_SIMPLIFY`, the run state records the implementation scope and requirements to preserve, and the handoff identifies concrete, behavior-preserving simplifications or explains why none are supported; Jev checks whether the implementation can stand as-is. A failed check sends the main agent back in the same loop with the suggested change and preservation requirements, at most `JevContinualSettings.max_continuations` times (default `JEV_DONE_MAX_CONTINUATIONS`); unavailable checks fail open. `agent.response.run_state`, `handoff`, `done`, and `continuations` report the outcome. The questions live in `vidbyte/lib/jev/done/`.
