# `vidbyte/tools/builtins/prebuilt`

## Folder Description / Intent

This folder holds the prebuilt tool library: 265 small, deterministic utility tools in 31 categories that an agent can call for jobs a language model does badly in its head. Counting the letters in a word, adding business days to a date, rounding money exactly, checking an IBAN, diffing two JSON documents, or splitting a CIDR block are all one tool call away, and every answer is computed rather than guessed. Each category is one module with one class, `<Category>ToolFunctions`, whose static methods are the tools; the docstring of each method is the description the model reads, and its annotated parameters become the tool's JSON schema.

Every tool runs on the Python standard library alone. No tool opens a file, a socket, or a process, reads an environment variable or the clock, or uses unseeded randomness, and none changes interpreter-wide state such as the decimal context or the integer digit limit. The same arguments therefore give the same output on every call, in every process, under any hash seed, working directory, time zone, or locale, within one Python version.

This folder is not the place for tools with side effects, for a general expression evaluator, or for agent wiring. Network, filesystem, shell, and code-execution tools live in the other built-in modules and the filesystem layer; arithmetic over expressions is the existing calculator tool; and the catalog that turns these functions into `FunctionTool` objects is `PrebuiltTools` in the toolsets layer. Nothing here imports the toolsets or agents layers.

### Attaching tools

Application code never calls the category classes directly. It builds a `PrebuiltTools` catalog from the categories an agent needs, or picks single tools from the full library with the inherited `subset` method:

```python
from vidbyte import Agent
from vidbyte.lib.enums import PrebuiltToolCategory
from vidbyte.tools.toolsets import PrebuiltTools

tools = PrebuiltTools([PrebuiltToolCategory.DATES, PrebuiltToolCategory.TEXT_COUNTING])
agent = Agent(name="assistant", system_prompt="Use tools for exact answers.", provider="openai", model_name="gpt-4.1", tools=tools)

picked = PrebuiltTools(PrebuiltToolCategory).subset(["days_between_dates", "count_character_occurrences"])
```

`PrebuiltTools` accepts only `PrebuiltToolCategory` members, one or many, and raises `ToolRegistryError` naming every other value, plain strings included. It builds fresh tools on every construction and caches nothing, so two catalogs never share a tool object. Every tool is an ordinary `FunctionTool` with `SAFE` permission, so it works with every provider schema, permission policy, and runner the SDK already has.

**Do not attach the whole library to one agent.** `PrebuiltTools(PrebuiltToolCategory)` is allowed, but the schemas of all 265 tools then travel with every model request, which costs much more and makes the model pick the right tool less often. Choose the few categories a task needs, or use `subset` for single tools. There is deliberately no "attach everything" default.

A direct call to a category method skips the schema validation that `FunctionTool` applies before running a tool, so caps, patterns, bounds, and enum conversion are not enforced and the method may receive values it was never meant to see. Run tools through a catalog.

### Output and error contract

- **Output.** On success a tool returns one JSON object with exactly the keys its row in the spec's Appendix A lists. Enum choices appear as their string values, dates and times as ISO 8601 text with seconds always shown, and datetimes always carry a UTC offset; a naive datetime argument is read as UTC.
- **Positions and lines.** Text positions are 0-based indices of Unicode code points into the original text, so an emoji counts once. Lines and columns are 1-based; a line break is CRLF, LF, or CR, and a trailing break does not start an extra empty line.
- **Exact numbers.** Integers that may grow large, exact decimals, and fractions are returned as canonical text (no leading zeros, no exponent, fractions in lowest terms). Integer results of more than 4,000 digits are refused. Money is rounded half up to cents exactly once, and floats are always finite.
- **Caps.** Every text and list argument has a schema cap. A list result with a `truncated` key keeps at most 1,000 items (or the row's own cap) and at most 1,000,000 characters of compact JSON, while its count keys still count every item. A tool whose output would pass 1,000,000 characters refuses before building it.
- **Errors.** An argument that breaks the schema fails with `error_type` `validation`, naming the argument. A well-formed argument that is wrong in meaning, such as an impossible date range or text that is not JSON, fails with `error_type` `ToolExecutionError` and the message `Invalid value for '<parameter>': <problem>. Expected <expected>.`; no other exception escapes a tool, and messages never repeat long stretches of an argument.

### Version-dependent behavior

Results are reproducible within one Python version, but a few depend on the running interpreter. The `seeded_*` tools reproduce their output for the same seed only within one Python version, because Python guarantees the same sequence only for `random()` itself. `verify_python_syntax` and the other code tools parse with the running interpreter's grammar, so syntax new in a later Python is invalid on an earlier one; the output reports the Python version used. The `ipaddress` flags behind `classify_ip_address`, and the text form of IPv4-mapped IPv6 addresses, follow the running Python's tables, which change between releases. Unicode names, categories, and scripts follow the running Python's `unicodedata` version. `strip_html_tags`, `extract_html_links`, and `html_table_to_records` drop markup left open at the end of the input, such as `x <b`, before they close the parser, so that tail gives no text, link, or cell on any release. CPython releases before 3.11.13, 3.12.11, and 3.13.4 re-scan such a tail once for every `<` in it (CVE-2025-6069), and the fixed releases changed what it produces. Other malformed markup follows the running `html.parser`, so a CPython security release can change these tools' output on it within one minor version.

### Limitations and secrets

The regex tools use the standard `re` module, which has no timeout. A pattern with catastrophic backtracking, such as a nested quantifier over a long run that cannot match, can run for a very long time; the pattern and text caps shrink the risk but do not remove it, and `FunctionTool` only gives up waiting when `ToolSettings.tool_timeout_seconds` is set, while the worker thread keeps running until the match ends.

`diff_words`, `closest_string_matches`, and `unified_diff_text` use the standard `difflib` matcher, which finds one matching block at a time and rescans the remaining text for each. On highly repetitive input at the caps, such as the same few short words or lines repeated many times with small differences, the work grows with about the cube of the input length, so a call can take tens of seconds instead of the usual fraction of a second, and case-insensitive matching can first triple the length of text with ligatures. The caps on tokens, candidates, candidate length, and lines bound the work, so the call always finishes with a correct result; `ToolSettings.tool_timeout_seconds` bounds how long the agent waits, and after a timeout the worker thread finishes the call and its result is discarded.

Tool arguments are recorded in transcripts and traces like every other tool argument, so a secret passed to a tool, such as an HMAC key, a JWT, or the text of an environment file, ends up there too. `compute_hmac` never repeats its key in an output or an error, and `decode_jwt_payload` only decodes: it always reports that the signature was not verified, so its claims must not be trusted. No tool reads the environment or files, so no tool can pull a secret in by itself.

## Non-Goals

- Do not add tools that use the network, read or write files, or start processes; the SDK's other built-ins and the filesystem layer own those jobs.
- Do not add IANA time-zone tools; `tzdata` is not a dependency, so the time tools use fixed UTC offsets only.
- Do not add a tool-search or tool-retrieval meta-tool; attaching by category keeps the tool count small.
- Do not add a tool whose answer depends on the clock, such as the current date; tools that need "today" take a reference date argument instead.
- Do not use the `locale` module or add languages other than English for number words, sentences, syllables, or relative dates.
- Do not add a YAML parser; alias expansion in YAML lets a short hostile document use up memory.
- Do not duplicate the calculator or other existing built-ins, such as a general expression evaluator; overlapping tools make the model pick the wrong one.
- Do not add a regex timeout or a killable regex worker here; the limitation is documented instead.
- Do not add `BaseTool` subclasses, registry discovery, or root `vidbyte` exports for these tools; they are reached only through `PrebuiltTools`.

## File Index

- `__init__.py` - Re-exports the 31 `<Category>ToolFunctions` classes, one per category, for the toolset and the test pack. It builds no tool and defines no function, so importing the package only defines classes. The package is deliberately not re-exported from the parent built-ins package, which keeps that package's export list unchanged. A new category adds its class import and its `__all__` entry here.
- `_support.py` - Holds `PrebuiltToolSupport`, the shared helpers every category uses, and the `PrebuiltToolOutput` and `PrebuiltToolFunction` type aliases. It owns the one argument-error builder, JSON and record parsing with the nesting cap, exact number text with the digit cap, the numeric text rule, item capping under the character budget, paired lists and weights, date and offset parsing, the fresh decimal context, the natural and numeric sort orders, tolerant Base64, the HTML end-of-input step, the shortening of names an error message lists, and the line, word, sentence, syllable, CSV, and encoding rules. Open it before writing any parsing or rule that a second category could need, because each rule exists exactly once. Its helpers call nothing else in the class except the error builder and the nesting measure.
- `exact_arithmetic.py` - Defines `ExactArithmeticToolFunctions`: exact decimal and fraction arithmetic, rounding to places or significant figures under a chosen rounding mode, exact sums, conversions between decimals, repeating decimals, and fractions, integer square roots, and quadratic equations. Decimal work runs in a local decimal context, never the global one. Results are canonical text so they carry no binary floating-point error.
- `number_theory.py` - Defines `NumberTheoryToolFunctions`: primality with deterministic Miller–Rabin, factorization, prime ranges, the nth prime, the next or previous prime, greatest common divisors, least common multiples, divisors, and modular exponentiation and inverses. Every bound comes from a named constant so each call finishes quickly. Counts and sums of divisors beyond the item cap are still exact.
- `number_formatting.py` - Defines `NumberFormattingToolFunctions`: base conversion, English number words in both directions, abbreviated numbers such as thousands and millions, separator styles in both directions, and scientific or engineering notation. The word, suffix, and currency tables come from the constants module. Parsing accepts only the forms its row lists and fails with an argument error on anything else.
- `descriptive_statistics.py` - Defines `DescriptiveStatisticsToolFunctions`: summaries, modes, percentiles and quartiles under named methods, weighted means, Pearson and Spearman correlation, linear regression, moving averages, outlier detection by interquartile range, and ranking. Spearman correlation is computed by hand so it does not change with the Python version. Every float output is checked to be finite.
- `probability.py` - Defines `ProbabilityToolFunctions`: exact combination and permutation counts, exact factorials, binomial and Poisson probabilities with a chosen tail, normal distribution probabilities and quantiles, the birthday collision probability, and listing combinations. Counts are computed with formulas and never by enumerating, so huge counts return at once. Listing stays within the item cap.
- `seeded_random.py` - Defines `SeededRandomToolFunctions`: seeded integers, shuffles, samples, weighted choices, dice notation rolls, and seeded version 4 UUIDs. Every tool builds its own `random.Random` from the seed and never touches the global generator. The same seed gives the same result within one Python version.
- `finance.py` - Defines `FinanceToolFunctions`: compound interest, loan payments and amortization schedules, net present value, internal rate of return, compound annual growth, percentage change, percentage breakdowns, allocations, and tax-inclusive splits. Money steps are exact fractions rounded half up to cents once, and only compound growth uses a fixed 50-digit decimal context. Shares and allocations hand out leftover units by largest remainder.
- `unit_conversion.py` - Defines `UnitConversionToolFunctions`: conversions of length, mass, temperature, volume, area, speed, duration, energy, fuel economy, and data size. The factors are exact text in the units constants module, so a conversion multiplies exact fractions and rounds once at the end. Temperature is affine and fuel economy may be inverse, so both have their own formulas.
- `dates.py` - Defines `DatesToolFunctions`: days between dates, adding days, weeks, months, or years, calendar differences, weekdays, ISO weeks, the nth weekday of a month, the next or previous weekday, relative date phrases against a reference date, free-form date parsing, and fiscal quarters. Date arithmetic uses `date` objects only, so there is no time-zone or clock input. Dates beyond the calendar's range fail as argument errors.
- `scheduling.py` - Defines `SchedulingToolFunctions`: business days between dates and added to a date with holidays, lists of dates in a range, weekday counts, recurring dates, merged time intervals, common free slots, and date sorting. Spans are bounded by named constants so lists stay small. Every datetime is timezone-aware.
- `timestamps_durations.py` - Defines `TimestampsDurationsToolFunctions`: Unix timestamps in both directions, fixed UTC offset conversion, durations between datetimes, adding durations, formatting and parsing durations, and minutes between times of day. Floats become exact output through one decimal quantize at the row's unit, and totals are rounded before they are split into parts. Unix time is counted from an aware epoch, never read from the clock.
- `text_counting.py` - Defines `TextCountingToolFunctions`: character counts by kind, occurrences of one character, substring positions, word, sentence, and line counts, word, character, and n-gram frequencies, the character at a position, readability scores, and syllables. Positions count code points and case-insensitive searches never shift them. Tallies run through `collections.Counter` so a long text is counted quickly.
- `text_transform.py` - Defines `TextTransformToolFunctions`: reversing text, identifier case conversion, shortening, literal replacement, line deduplication and sorting, HTML tag stripping, chunking with overlap, line ranges, and template filling. Tools that could amplify their input predict the output size and refuse before building an oversized result. Rebuilt text joins lines with a line feed and keeps one trailing break when the input had one.
- `unicode.py` - Defines `UnicodeToolFunctions`: character information and search by name, normalization forms, diacritic removal, invisible and non-ASCII character reports, script detection, encoded sizes, SMS segment counts, and mojibake repair. It reads Unicode facts from the running Python's `unicodedata`, so new characters can differ between versions. The GSM-7 tables and code point sets come from the constants module.
- `regex.py` - Defines `RegexToolFunctions`: finding all matches, matching in full, prefix, or search mode, replacement, splitting, pattern checks, sample testing, and wildcard name matching. Pattern and text caps limit the cost, but the standard `re` module has no timeout, which the folder description records as a known limitation. Match listings stop at the item cap and the character budget while the counts stay complete.
- `text_comparison.py` - Defines `TextComparisonToolFunctions`: unified diffs, word diffs, Levenshtein distance, closest string matches, the longest common substring, and Jaccard similarity. Each pairwise algorithm has its own input cap so its time and memory stay bounded. Results are ordered deterministically.
- `json_data.py` - Defines `JsonDataToolFunctions`: JSON syntax checks, formatting, reading and setting values by JSON Pointer, listing paths, diffing documents, applying JSON Patch, summarizing structure, and extracting JSON embedded in text. Every document is parsed through the shared helper with its nesting cap. Formatting predicts its output size and patching keeps a running size, and both refuse results over the output cap.
- `json_records.py` - Defines `JsonRecordsToolFunctions`: filtering, plucking, grouping, aggregating, sorting, counting values, joining record sets, and writing records as CSV. Numeric comparisons follow the shared numeric text rule. Joins and CSV output are bounded by the record, column, and output caps.
- `csv_tables.py` - Defines `CsvTablesToolFunctions`: CSV to records, dialect detection, column profiles, filtering, sorting, aggregating, grouping, joining tables, and Markdown table output. Every table is read through the shared CSV helper, which sniffs a bounded prefix and checks the header. The field size limit of the `csv` module is never changed.
- `structured_formats.py` - Defines `StructuredFormatsToolFunctions`: XML to JSON, XML well-formedness, XML element search, INI and TOML to JSON, URL parsing and resolution, query strings, and dotenv text. XML with a document type or entity declaration, or with an overlong namespace URI, is refused before parsing, and nesting is capped for every format. Path errors that the standard library raises in different forms all become one argument error.
- `encoding.py` - Defines `EncodingToolFunctions`: Base64 and hex in both directions, URL encoding and decoding, HTML unescaping, JWT payload decoding without verification, and JSON string escaping in both directions. Decoded bytes come back as text when they decode in the chosen encoding, always with a bounded hex preview. A decoded JWT always reports that its signature was not verified.
- `hashing.py` - Defines `HashingToolFunctions`: text and Base64 content hashes, HMACs, hash comparison, CRC-32, Git blob hashes, and stable bucket assignment. MD5 and SHA-1 are created with `usedforsecurity=False` because they serve checksums only. The HMAC key never appears in an output or an error.
- `identifiers.py` - Defines `IdentifiersToolFunctions`: Luhn, ISBN, IBAN, and GTIN checks, email and URL syntax checks with named problems, UUID checks, name-based UUIDs, and semantic version comparison. Syntax problems are reported in a fixed order from enum vocabularies. Nothing is looked up online, so a valid result means well-formed, not existing.
- `lists.py` - Defines `ListsToolFunctions`: item frequencies, duplicates, comparisons and intersections of lists, missing integers, and integer range compression and expansion. Huge counts are computed arithmetically instead of by enumerating. Case-insensitive comparison uses case folding and reports the first spelling seen.
- `graphs.py` - Defines `GraphsToolFunctions`: topological sorting, cycle detection, shortest paths with and without weights, connected components, and critical path schedules. Nodes are visited in first-appearance order or explicit sort order, never set order. Edge and task counts are capped by named constants.
- `geometry.py` - Defines `GeometryToolFunctions`: great-circle distance, initial bearing, destination points, conversions between decimal degrees and degrees-minutes-seconds, polygon area and orientation, and point-in-polygon tests. Distances use the mean Earth radius and the exact length factors. Degrees are rounded once as a total before they are split into parts.
- `bits_bytes.py` - Defines `BitsBytesToolFunctions`: data size parsing and human-readable formatting in SI or IEC units, bitwise operations, two's complement in both directions, and Unix permission conversion. Bit widths are capped by a named constant. Size labels come from the constants module.
- `markdown_html.py` - Defines `MarkdownHtmlToolFunctions`: Markdown headings, tasks, tables, links, and fenced code blocks, plus HTML tables as records and HTML links. HTML is read with private `HTMLParser` subclasses, never by executing anything. Table outputs keep a running size and refuse results over the output cap.
- `text_extraction.py` - Defines `TextExtractionToolFunctions`: extraction of URLs, email addresses, numbers, dates, IP addresses, money amounts, key-value pairs, and sentences from free text. Extraction lists stop at the item cap and the character budget while counts stay complete. Currency codes and symbols come from the constants module, and an extracted currency repeats the input text.
- `code_analysis.py` - Defines `CodeAnalysisToolFunctions`: Python syntax checks, function and class listings, imports, signatures, name usages, Python literals as JSON, lines of code by language, and shell command splitting and quoting. Python source is only parsed with `ast`, never compiled or run, and `ast.literal_eval` appears only for literal conversion with a nesting cap. Results follow the running interpreter's grammar.
- `network_addresses.py` - Defines `NetworkAddressesToolFunctions`: IP address checks with named problems, CIDR details, membership tests, subnet splitting, ranges as CIDR blocks, address classification, integer conversion, and IPv4 netmask conversion. Subnet counts are computed arithmetically, so even an IPv6 split into 2^128 parts answers at once. Classification flags follow the running Python's `ipaddress` tables.
