## Purpose

The conditions that are all true when the task is done. The verifier judges the work against each one, fixes what falls short, and bases its verdict on them.

## How to write it

Write each condition as a concrete, observable outcome that another agent can confirm by reading the workspace, running a check, or consulting a named source. Say where the result must be and what form it takes, and state the quality bar plainly, such as how claims must be supported. Prefer several specific conditions to one broad one, because the verifier reports on each condition separately.

## Rules

The list must hold at least one condition. A condition that cannot be checked gives the verifier nothing to judge, so it leads to a failed verdict or an empty pass.
