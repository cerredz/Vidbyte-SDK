# Test plan: provider-onboarding-skill

Spec: `docs/spec/provider-onboarding-skill/spec.md` r3 · Framework: pytest 8.3.5 (plain test functions, PyYAML 6.0.2 for the frontmatter) · Prior art copied: `tests/features/agent_output_connectors/test_output_connectors_contract.py` (static file reads, `REPO_ROOT = Path(__file__).resolve().parents[3]`), `tests/features/sdk_provider_keys/` (pack layout: README, FEATURE, `*_fixtures.py`, tests named by the failure they catch)

Pack: `tests/features/onboard_model_provider_skill/`, which holds `README.md`, `FEATURE.md`, `onboard_skill_fixtures.py` and five test modules with 46 tests. Codes in brackets (A1, C4, W6, X3, S2) are the pack's own test codes, written in each test's first comment and in `FEATURE.md`.

The deliverable is Markdown an agent executes, so most tests are static contract tests over the two skill files and `REPO_MAP.md`. The integration tests run the skill's own `sed -n 's/…/…/p'` extraction commands, through a POSIX BRE emulator in the fixtures, over the real repository files and the real wiring table. They also check every path and symbol the checklist names against the tree. The D-29 test calls the real `Runner._normalize_provider_and_model`. No test reads git state, the network, `gh` or Claude, and no test pins the provider list, the member count, `PRICING_AS_OF` or a line number, so every test stays valid inside every provider PR the skill opens (spec §13, R-1).

| Running preflight or pass-top commands live (AC-1 behavior) | Needs the network and `gh`. Their parsing is executed offline (X3, W6), and the live run is PR-time evidence. |
| Wheel contents / package stage (AC-11, INV-25) | Needs a build. The gate's package stage is the test. |
| End-to-end session of the skill | `disable-model-invocation: true` blocks agent invocation, and a Claude session cannot run in pytest. |
| Seed slugs are not yet `ModelProvider` members | False on the first provider branch (forbidden by the brief). |
| Pinning seed display names, URLs or reason text | A reviewed seed edit would need a second edit here without protecting a spec rule. C5 tests the security property instead. |
| Pinning `PRICING_AS_OF`, the member count or list, or line numbers | Each provider PR changes them. X3 compares with values imported from the same tree. |
| Brief length ≤ 40 lines (NFR-2) | The §8.5 template is 12 lines, and C6 pins its content. A length bound adds no failure mode the field checks miss. |
| Property, fuzz or metamorphic tests | No algebraic invariant in code. The loop is prose a model executes. |
| Concurrency or idempotency of two sessions (EC-52) | A runtime behavior against live GitHub. The text guards (skip rules, one session, single unforced refspec) are tested. |
| URL liveness of the seed pages | Network-dependent and drifting by design. |
| `description` semantics beyond length and non-emptiness | Free text for the skill listing. The stop conditions are tested where a person reads them (A3). |
