## What the implementation gets right (so nobody "fixes" it)
- **The loop.** The runtime is the inherited linear loop plus exactly three hooks (`_after_tool_iteration`, `_continue_finish_attempt`, `_budget_stop`) and one private step, `_rebuild_history`. It calls `super().arun` once. NFR-3 introspection shows exactly those overrides.
- **The rebuild.** It calls `ContextCompactionEngine().compact_provider_messages(..., TRIM_WITH_PROVIDER_BOUNDARIES, {"max_messages": 1})` and assigns `messages[:] = list(kept)`. It runs from both hooks; on a refused finish it runs before the gap message. It is counted only when `removed_count > 0` (runtime.py:136-177). A probe on Anthropic, Gemini, and OpenAI histories keeps whole call/result groups, including the bulk-call + refused-`isDone` turn. This is D-11/INV-30 as the user decided.
- **Roles are enforced by the catalog, not the prompt.** Handles map to a role only by their queued name `browser-<role>-<n>` (tools.py:47). The run catalog is `self.tools.without(action).extend((episode, goal.tool()))` (runtime.py:116). Workers get the same bridged ACTION tool objects, so every episode shares one server process (INV-5, INV-7, AC-5, AC-6).
- **Goal card and recheck.** The card is a frozen record. `patch_goal` takes the section as an enum, accepts only plan, progress, and blockers, and progress only grows. Each recheck is a newly built `BaseAgent` with `system_prompt_presets=()` that sees only the goal, done_when, and progress (goal.py:228-260). The stall rule follows D-14 (goal.py:126-145).
- **Keys.** They live only in `BrowserServerSettings.env` and the model-key fields, all `repr=False` (settings.py:70, :136-137). They are checked by the canonical `McpPresetRegistry.build_config`, and `os.environ` is never read. A blank or `os.environ`-only key is refused. The duplicate-server error names only the program (settings.py:243-252).
- **Caps live in code.** Every cap is a constant plus a check in code, and none of the 19 prompt leaves contains a digit. The validation-bound constants (`BROWSER_FIRST_INDEX`, `BROWSER_MIN_COUNT`, the caps) follow `strict-config-dataclasses.md`, so do not inline them back. The size requirement holds: the largest module is 251 body lines and the largest class is 166 lines.
- **Placement and layering.** The enums are in `vidbyte/lib/enums/browser.py` and exported. The records are in `vidbyte/lib/dataclasses/browser.py`, with `UsageRollup` imported only under `TYPE_CHECKING`. The settings are in `vidbyte/agents/browser/settings.py`. The registry imports `BrowserAgentRuntime` lazily. No file under `vidbyte/tools`, `vidbyte/middleware`, or `vidbyte/cli` changes. A006, S015, and C016 add no findings.
- **Headers and comments.** Every new production module has the full A001 header (the R-9 wording slips aside). Every comment line added under `vidbyte/agents/browser/` and `vidbyte/lib/*/browser.py` is ≤ 72 columns.
- **Prompt family.** It follows `prompt-families.md` and `model-facing-tool-contracts.md`: no digits, 4–5 sentence descriptions, no `format(max_`. The header of `vidbyte/lib/enums/prompts.py` ("158 assets across 36 families") matches a recount.
- **§12.5 docs.** The README `## File Index` matches the folder (S020) and `## Notes for agents` is present. README sizes (9,798 / 31,986 / 33,924) are ≤ 40,000. Commits are conventional and ID-tagged.
- **Per-run state.** It lives on the per-run runtime and its episode tool. `BrowserAgentRuntime.__init__` has no side effects, so BaseAgent can build `_runtime()` twice (base.py:1280, :1319) safely, and AC-23 covers the counter reset.
- **Stuck cards.** The path is correct in both branches (episode.py:118-124). `OutputSchemaViolationError` is caught first and the card is built from `worker.last_reply`, which is set before the raise (base.py:1009 before :1022). Other SDK, OS, and value errors give an error card. `CancelledError` propagates. Every error BaseAgent re-raises unwrapped is a `VidbyteSdkError`, so none escapes an episode.
