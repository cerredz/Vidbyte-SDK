# Test plan: BrowserAgent — episodes, a pinned goal card, and fresh-context rechecks

Spec: `docs/spec/browser-agent/spec.md` r3 · Framework: pytest 8.3.5 + pytest-asyncio 1.3.0 (strict mode, `--strict-config --strict-markers`) · Prior art copied: `tests/features/infinite_memory_agent/` (`infinite_memory_fixtures.py`, `test_infinite_memory_contract.py`)

Pack: `tests/features/browser_agent/` — 8 test modules, 69 test functions, 106 collected items. Abbreviations below: `acc` = `test_browser_agent_acceptance.py`, `con` = `_contract`, `set` = `_settings`, `epi` = `_episode`, `goal` = `_goal`, `rch` = `_recheck`, `reb` = `_rebuild`, `obs` = `_observability`. "Feature" level means a real `BrowserAgent.run`/`arun` with only the model runner and the MCP stdio transport faked (spec §13). Two guards apply to every feature-level test and are not repeated per row: `ScriptedModel.assert_complete()` fails on any model call the script did not expect, so an agent the feature must not run cannot pass silently, and every count of browser actions is a count of `tools/call` requests the fake server received, not of model turns.

- Seams: the model runner is patched at `BaseAgent._runner_for_model` and answered by agent name: the orchestrator is `settings.name` (`vc-scout`), workers `vc-scout-episode-<n>` (1-based), rechecks `vc-scout-recheck`, the done-when agent `vc-scout-done-when`. The stdio transport is patched at `vidbyte.tools.mcp.attach.McpStdioTransport`. Keep those names and that import path.
- Fake replies report `gpt-5.4-mini` (`PRICED_MODEL`), the §4 model since spec r4. A model with no pricebook row (such as `gpt-4.1`, the r1–r3 snippet model) makes the run raise `UsageAccountingError` (INV-21).
- The property tests build `BrowserGoal(BrowserGoalCard(goal, done_when), settings, BrowserResponse(), BrowserAgentEvents(None))` directly, so `BrowserResponse()` must take no arguments (as `JevResponse()` does), and `BrowserGoal.patch` must raise `ConfigurationError` on refusal. `agent.response.goal` is checked only after an accepted patch.
- Tool sets: the loop adds `isDone` to every `BaseAgent` catalog, so the tests allow `isDone` beside the ACTION tools (workers) and as the only tool of a recheck.
- A worker's provider error reaches the episode tool wrapped in `AgentExecutionError` (cause `ProviderRequestError`); the stuck card's `stop_reason` may name either.
- Prompt wording is read from the catalog (`Prompt.BROWSER_AGENT_<LEAF>`), never copied into tests; `template_regex` matches a filled leaf, and `distinctive_line` picks a line that only one leaf has. Changing a leaf's wording is safe; changing its placeholders is not.
- Role names must come from `BROWSER_SERVER_NAME_TEMPLATE` (`browser-<role>-<n>`); the tests accept 0- or 1-based `<n>`, consecutive per role.
- Do not modify these tests (§14). If one looks wrong, report it with the spec ID instead.
