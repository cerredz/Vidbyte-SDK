## What the implementation gets right (so nobody "fixes" it)
- **Item 1, read window.** AC-1 holds byte for byte: the §4 snippet prints `[lines 1-200 of 1000 shown; read on with start=201]`, `True 1000 201`, `200 True`. INV-1.x hold, and the `LineLimit` rename keeps the old refusal text. With no window, output, metadata and spec equal main.
- **Item 6, bash head and tail.** The split follows §8 exactly: T = min(25,000, MAX//2), H = MAX − T, and the marker appears only when bytes were left out. Head and tail are joined before decoding when nothing is omitted. Memory stays at H+T bytes plus a count. The omitted count lives in a one-item list, so it survives `wait_for` cancellation, and the over-cap timeout test runs on Windows and passes.
- **Item 7, stable root prefix.**
  - `_build_system_string` drops the loop block, and the map is drawn once per run.
  - At most one user status message follows each tool iteration. The `map_update` leaf appears only on a change, cut by the shared `fit_map_lines`.
  - Mutation `mut_status` (baseline never advanced) is caught by 4 stable-prefix tests.
- **Item 9, Anthropic cache marks.**
  - Marks are block-level `{"type":"ephemeral"}` only, never top-level and never with `ttl`. They are added only when the sha256 of [tools, system] repeats, at most 3 per request.
  - Marks go only on copies. Mutation `mut_mark` (marking the caller's blocks) fails 12 of 14 tests, `NoMutationTests` among them.
  - The digest set is cleared at 256, and each agent has its own adapter (`_runner_cache`), so one agent's digests never evict another's.
- **Items 2 and 4, middleware.**
  - Order is masking → trim → limits on every agent and the retriever.
  - Masking is scoped to `INFINITE_MASKED_TOOL_NAMES` (keep 3, STRIP, placeholder leaf). It never touches inputs or `launch_subagent`, and it works on the OpenAI, Anthropic and Gemini wires (tool names are resolved through the tool_use id map).
  - No `DeduplicateToolCallsCompaction` is installed anywhere (NG-5).
- **Quantized trim (INV-4.2).** It does what D-5 promised. In a 600-iteration simulation, the first kept message moved on 13/281, 10/254 and 11/283 calls, against 265/281, 228/254 and 275/283 for main's exact-cap trim. `_greedy_keep` is main's algorithm unchanged.
- **Item 10, recall.**
  - Found text is copied from disk under code-built labels.
  - The bookkeeping refusal holds against Windows aliases (`SUPERSEDED.JSONL`, trailing dot or space, `::$DATA`, `./`), with a casefold check after `resolve_scoped_path`.
  - The quota check and its increment have no `await` between them.
  - `TimeoutError` is caught, as an `OSError`.
  - Recall is opt-in with DIRECT as the default (Q-1) and is withheld from verifiers.
- **Item 8, search_memory.**
  - The lock is held across refresh and search inside `asyncio.to_thread`. `_table()` opens lazily under the lock, and `check_same_thread=False` is set.
  - The FTS query takes 0.1 ms, and the cold build at the caps takes 1.3 s, inside NFR-8.1's 2 s.
  - Every hostile query other than NUL and lone surrogates returns a normal result: `price:59 "x" NEAR(a b) -c *`, `^zeta`, `zeta*`, `{a b}`, `AND OR NOT`, `"`, `a"b"c`, `col:`, `:`, `+a`, combining marks, a zero-width space, `é`.
  - `entries.jsonl` is never dropped for size (`largest_file_bytes = max_tokens × 16`).
