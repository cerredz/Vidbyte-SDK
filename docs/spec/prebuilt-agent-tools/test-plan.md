# Test plan: A library of 250+ prebuilt agent tools in vidbyte-sdk

Spec: `docs/spec/prebuilt-agent-tools/spec.md` r3 · Framework: pytest 8.3.5 with pytest-asyncio 1.3.0 (strict mode; the pack uses `asyncio.run` inside plain tests, so no marker is needed) on Python 3.11.0 · Prior art copied: `tests/features/sdk_operation_costs/test_operation_cost_contract.py` (pack and header shape), `tests/features/coding_agent/conftest.py` (lazy feature import inside fixtures), `tests/test_function_tool_parameter_types.py` (the `FunctionTool` validation seam)

Pack: `tests/features/prebuilt_tools/`. It has 19 test files, 4,284 collected tests, and 4 support modules (`conftest.py`, `prebuilt_tool_harness.py`, `prebuilt_catalogue_data.py`, `prebuilt_parameter_data.py`), plus `FEATURE.md` and `README.md`. Each Appendix A tool has at least one exact-output case at the model seam. The row files hold 1,339 success cases and 511 failure cases, and each row-group file adds a few property tests.

## Tests deliberately NOT written

| Candidate | Why it would not earn its keep |
|---|---|
| Wall-clock assertions: AC-15 "within 1 second", AC-20 "within 2 seconds", NFR-7 build time ≤ 2 s / ≤ 3 s, EC-37 about 1 s | Rule 3 forbids wall-clock dependence, and timings flake on shared CI. The design properties behind them are asserted structurally instead: refusal before building (tracemalloc peak), arithmetic counts that cannot finish if enumerated, and pre-computation size checks. |
| INV-23 (root `vidbyte.__all__` and `contracts/sdk-public-api.json` unchanged), INV-24 (`vidbyte.tools.builtins.__all__` unchanged), INV-25 (dependencies unchanged) | These pass today, so they would be vacuous red tests. Existing gates already enforce them: `scripts/generate-sdk-public-api.py --check` (C016), `scripts/check_reasoning_trace_contracts.py`, and the package stage. |
| INV-26 (the runtime treats prebuilt tools like any `FunctionTool`) | There is no new runtime code path to observe. The runtime's existing suites cover timeout, truncation, and policy. AC-1 builds an `Agent` with a prebuilt catalogue end to end. |
| INV-3 collision with existing SDK tool names, as a runtime test | It would pass before implementation. The names are pinned exactly by AC-3 and INV-1, and S2 checked statically that none of the 265 Appendix A names equals any of the 743 existing SDK name literals. |
| EC-14 lone surrogate through `hash_text`, `base64_encode`, and `count_bytes_in_encoding`; `unicode_character_info` `utf8_hex: null` | It is unreachable at the model seam: `FunctionTool._validate_arguments` serializes to JSON and pydantic JSON mode rejects `"\ud800"` with a validation error. | Cross-version pins (EC-24 seeded draws, EC-25 PEP 695 grammar, EC-26 `ipaddress` flags of 100.64.0.1, EC-38 new Unicode characters) | They would fail on one of the two CI Pythons. | EC-10 catastrophic regex backtracking | It is an accepted limitation, and a test would hang. |
| EC-28 timeout, EC-27 parallel threads, EC-40 hot-loop rebuild cost | These are runtime or performance behavior with no tool-side contract to observe deterministically. Statelessness is covered by INV-6, INV-13, and the repeated-call determinism test. |
| A meta-test that every Appendix A tool has a success case | It would pass before implementation, which is not red. Coverage was verified by script instead: 265 of 265 tools, 1,339 success cases, 511 failure cases. |
| Random (unseeded) fuzzing or hypothesis | Failures would not reproduce. The schema-derived sweep is deterministic and edge-biased. |

## Notes for the implementer

- The pack binds to exactly these names: `vidbyte.tools.toolsets.PrebuiltTools`, defined in `vidbyte.tools.toolsets.prebuilt` (the test checks `__module__`), with static methods `select_categories` and `get_tools`; `vidbyte.lib.enums.PrebuiltToolCategory` and the other 67 enums, defined in `vidbyte.lib.enums.prebuilt_tools` or `vidbyte.lib.enums.units` and listed in `vidbyte.lib.enums.__all__`; and `vidbyte.tools.builtins.prebuilt.<Category>ToolFunctions.tool_functions()`, whose functions live in `vidbyte.tools.builtins.prebuilt.<category value>` with `__qualname__` `<Category>ToolFunctions.<tool>`.
- The static scan requires `vidbyte/tools/builtins/prebuilt/` to contain `__init__.py`, `_support.py`, and one `<category value>.py` per category. `ast.literal_eval` is allowed only in `code_analysis.py`. md5 and sha1 must be built as `hashlib.md5(..., usedforsecurity=False)`, `hashlib.sha1(..., usedforsecurity=False)`, or `hashlib.new("md5", ..., usedforsecurity=False)`.
