# Test plan: A library of 250+ prebuilt agent tools in vidbyte-sdk

Spec: `docs/spec/prebuilt-agent-tools/spec.md` r4 (the pack was written against r3 and tightened to r4; see "Spec r4 tightening") · Framework: pytest 8.3.5 with pytest-asyncio 1.3.0 (strict mode; the pack uses `asyncio.run` inside plain tests, so no marker is needed) on Python 3.11.0 · Prior art copied: `tests/features/sdk_operation_costs/test_operation_cost_contract.py` (pack and header shape), `tests/features/coding_agent/conftest.py` (lazy feature import inside fixtures), `tests/test_function_tool_parameter_types.py` (the `FunctionTool` validation seam)

Pack: `tests/features/prebuilt_tools/`. It has 19 test files, 4,310 collected tests, and 4 support modules (`conftest.py`, `prebuilt_tool_harness.py`, `prebuilt_catalogue_data.py`, `prebuilt_parameter_data.py`), plus `FEATURE.md` and `README.md`. Each Appendix A tool has at least one exact-output case at the model seam. The row files hold 1,353 success cases and 523 failure cases, and each row-group file adds a few property tests.

## Spec r4 tightening

Spec r4 (commit `5d93fe88`) fixed the values r3 left open. **No existing assertion contradicted r4.** Every change below either replaces an `ANY`, a range, or a "cap only needs to exist" sentinel with r4's exact value, or adds a case for behavior r4 newly states. Each value was read from its r4 Appendix A row, §9.2, or the S1 r4 addendum.

- **Schema caps (AC-7, INV-16).** The four `UtcOffset` parameters (`merge_time_intervals.output_offset`, `find_common_free_slots.output_offset`, `unix_timestamp_to_datetime.utc_offset`, `convert_utc_offset.to_offset`) now need the pattern and `maxLength` 6. `add_business_days.holidays` needs 1,000 and `weekend_days` 7. Both `critical_path_schedule` dependency lists need 10,000. The `ANY_CAP` and `PATTERN_BOUND` sentinels are gone, and the cap test gained `convert_utc_offset` and `unix_timestamp_to_datetime`.
- **Markdown (A.28).** The Setext heading `line` is its text line (10). The autolink `text` is the URL. Fenced blocks are exactly (2, 4) `print("hi")`, (5, 7) `let a = 1;`, and the unclosed (8, 10), whose `code` is the two lines `plain` and `unclosed`; no `code` ends with a line break. `test_malformed_html_table_never_raises` now requires columns named from the longest row.
- **JSON and CSV (A.17 to A.19).** `verify_json_syntax` NaN and depth-101 cases: null `line`, `column`, `position`. `detect_csv_dialect` fallback: `quote_character` `"` and `rows` 0. `profile_csv_columns` counts distinct values by text (3, with examples `02`, `2`, `5`). `csv_to_markdown_table` is compared as exact text for every alignment; the `-counts` case became `-auto-exact-text`.
- **Formats (A.20 to A.22).** `verify_xml_wellformed` entity-bomb and long-namespace cases: null positions. New cases: `plain-doctype`, `xml_find_elements` path `"@"` → error(`path`), and `hash_base64_content` with a padded `base64` digest.
- **Unicode and regex (A.14, A.15).** `verify_regex_pattern` reports `re.error.msg` and `.pos` exactly. `sms_segment_count` of empty text has 160 units per segment. New cases: `remove_diacritics` keeps non-Latin marks, and `find_invisible_characters` keeps TAB, LF, and CR.
- **Code analysis (A.30).** A plain import has `module` null and `names` as written, `as` included. Usage columns point at the name (16, 5, 8). The `get_python_function_signature` text is exact. A null character gives `valid: false` from `verify_python_syntax`, error(`literal`) from `python_literal_to_json`, and error(`source`) from the five other parsers.
- **Other rows.** `extract_numbers` percent `text` includes `%`. New cases: `verify_email_syntax` `domain_too_long` first, `verify_isbn` lowercase `x`, `fraction_to_decimal` truncated past 1,000 digits, `compute_quartiles` of two values, `convert_identifier_case` digit then uppercase, `sort_text_lines` numeric descending, two `extract_line_range` break cases, `format_duration` long without zero parts, `strip_html_tags` exact text, and the `fiscal_quarter`, `bitwise_operation`, and `business_days_between` errors.
- **Removed.** The parametrized `test_verify_xml_wellformed_reports_rejected_markup_with_a_message` (2 tests) only checked for a non-empty message, which the two row cases now state exactly with null positions. Two `add_business_days` over-cap `invalid` cases written during this pass were dropped again because AC-7 now checks those exact caps.

## Post-S3 fix (S3-3: `intersect_lists` nested lists)

**Defect.** S3 built all 265 tools and found a defect in the S2 test data, and the orchestrator ruled for the spec. `prebuilt_parameter_data.py` gave `intersect_lists.lists` an int item cap of 10,000, which treats each item as a string. Appendix A.24 types it as `list[TextList] len 2..PREBUILT_MAX_LISTS`, so each item is a list. Two contract cases failed against the row-following implementation: `test_tool_schema_matches_its_appendix_row[intersect_lists]` ("item maxLength is None") and `test_one_over_cap_argument_fails_validation_naming_the_parameter[intersect_lists]` ("lists.0: Input should be a valid array").

**Decision: teach both tests about nested arrays.** I chose this over setting the item cap to `None` plus a one-off check, because `None` would have dropped the inner caps from the behavioral test.
- The data module gains a `TextListsShape(min_lists, list_items, item_chars)` record. `LIST_OF_TEXT_LISTS = (2, 10000, 10000)` is read from A.24, §9.2 `TextList` (`PREBUILT_MAX_LIST_ITEMS` items, `PREBUILT_MAX_SHORT_TEXT_CHARS` per string) and `PREBUILT_MAX_LISTS` (100).
- The row is now `('lists', 'array', 100, LIST_OF_TEXT_LISTS, REQUIRED)`.
- `schema_problems` checks five things for a `TextListsShape`: outer `minItems`, inner type `array`, inner `maxItems`, string type, and string `maxLength`. The outer `maxItems` 100 is still checked by the existing cap line.
- `test_every_text_and_list_parameter_is_capped` now descends one level into a list whose items are lists.
- `over_cap_values` adds two cases for a `TextListsShape`: one inner list of 10,001 items (loc `lists.0`), and one inner string of 10,001 characters (loc `lists.0.0`). Each sends `min_lists` lists, so the outer minimum never fails beside them. The 101-list case is unchanged.

## Notes for the implementer

- The pack binds to exactly these names: `vidbyte.tools.toolsets.PrebuiltTools`, defined in `vidbyte.tools.toolsets.prebuilt` (the test checks `__module__`), with static methods `select_categories` and `get_tools`; `vidbyte.lib.enums.PrebuiltToolCategory` and the other 67 enums, defined in `vidbyte.lib.enums.prebuilt_tools` or `vidbyte.lib.enums.units` and listed in `vidbyte.lib.enums.__all__`; and `vidbyte.tools.builtins.prebuilt.<Category>ToolFunctions.tool_functions()`, whose functions live in `vidbyte.tools.builtins.prebuilt.<category value>` with `__qualname__` `<Category>ToolFunctions.<tool>`.
- The static scan requires `vidbyte/tools/builtins/prebuilt/` to contain `__init__.py`, `_support.py`, and one `<category value>.py` per category. `ast.literal_eval` is allowed only in `code_analysis.py`. md5 and sha1 must be built as `hashlib.md5(..., usedforsecurity=False)`, `hashlib.sha1(..., usedforsecurity=False)`, or `hashlib.new("md5", ..., usedforsecurity=False)`. Any `time.*()`, `os.*()` other than `os.path`, `.now()`, `.today()`, `strptime`, `getcontext`, `field_size_limit`, `uuid4`, or global `random.*()` call fails the scan.
- Default values in schemas are compared as JSON: enum defaults as value strings, tuple defaults as lists, and optional parameters as `anyOf` with `null` and `"default": null`. A `UtcOffset` must carry exactly the pattern `^(Z|[+-](0[0-9]|1[0-9]|2[0-3]):[0-5][0-9])$` and `maxLength` 6 (`PREBUILT_MAX_UTC_OFFSET_CHARS`). Every cap is compared exactly, including `add_business_days.holidays` 1,000 (`PREBUILT_MAX_HOLIDAYS`), `weekend_days` 7, and `critical_path_schedule.dependency_sources` and `dependency_targets` 10,000 (`PREBUILT_MAX_GRAPH_EDGES`), and every plain `str` parameter needs a `maxLength`.
- `ToolExecutionError` messages are parsed with `\AInvalid value for '(?P<parameter>[^']+)': (?P<problem>.+)\. Expected (?P<expected>.+)\.\Z`. Build them only through `PrebuiltToolSupport.argument_error`.
- Peak-memory tests allow 5 MB of traced allocation for calls whose refused output would be 20 MB or more (replace_all_occurrences, regex_replace, fill_text_template, format_json). Predict, or count while building; never build, then measure.
- `SchemaArgumentFactory` builds argument sets from your live schemas. A string schema with a pattern that none of its samples match makes it raise "add one to the pools". Fix that by adding a sample to `PATTERN_SAMPLES` in `prebuilt_tool_harness.py`, which is a fixture change, not an assertion change.
- r4 now states every interpretation the r3 pack had pinned on a loose row: unpadded `base64url` for all three `DigestFormat` users, single spaces in `number_to_english_words`, `time.isoformat()` for `time` keys, distinct-key `count` in `parse_dotenv_text`, distinct-value `count` in the `extract_*` rows, exclusive `end` in `extract_json_from_text`, and in-place replacement in `json_set_value`. Two readings remain the pack's own where r4 is silent, and reviewers should confirm them against the spec rather than change the tests casually. First, `get_python_function_signature` writes a function without a return annotation as `def run(self)`, with no arrow. Second, `detect_csv_dialect` `has_header` stays `ANY` in two cases, because the row does not say how the header is detected.
- `NON_EMPTY_TEXT` in an expectation accepts any non-empty string and nothing else. It stands only where r4 fixes an error as non-empty text without giving its words, such as a rejected DOCTYPE or a JSON depth error.
- The pack's runtime once green is dominated by the sweep tests: 13 calls per tool in the error contract, 6 in the side-effect tests, 3 in each of three determinism interpreters, and `find_unicode_character` at about 1 s per call (EC-37). The count tests (2^128 subnets, 10^15 integers, C(39,20) combinations) have no timeout of their own, so an implementation that enumerates hangs rather than fails; stop the run and read the test name.
