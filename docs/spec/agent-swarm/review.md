## What the implementation gets right (so nobody "fixes" it)

**Decomposition**
- The decomposition is the one the user asked for:
  - `AgentSwarm` (swarm.py:26-56) is a thin entry point. It holds the run flag, checks the goal, prepares the folder, and builds one fresh `AgentSwarmRuntime` per `arun`. Its `_running` flag is set and cleared in `try/finally`.
  - `AgentSwarmRuntime` (runtime.py:41) is the per-run coordinator.
  - `AgentSwarmEvents`, `AgentSwarmWorkplace` and `AgentSwarmTools` each have one role.
  - `AgentSwarmMemberRuntime` overrides one hook only: `_after_tool_iteration` (member.py:62-70).

**Concurrency and ordering**
- Every state check is followed by its change, and its event record, with no `await` in between. This holds in `post_message` (runtime.py:150-168), `end_turn` (:189-204) and `_end_check` (:260-271).
  - The idle mark, the wait future and the end check all run before the first `await` (:201-205), so the EC-1 race cannot lose a wake.
  - After `await wake`, state is checked again synchronously (:210).
  - Do not move these awaits. The pack kills the mutants that do so (M1, M1b), and the one that moves the wake into the woken agent (M20).
- A wake is decided at send time and counted against the budget (:164-168).
- QUIET, MAX_TURNS and FAILED are decided exactly as INV-10 states (:262-268).
- `self._stop_reason or TIMEOUT` (:101) is the EC-18 rule; M7 shows that it matters.
- The swarm never sleeps or polls (NFR-2).
- Exactly-once delivery and causal order hold:
  - `_drain` (:239-241) takes the inbox and records each `MESSAGE_DELIVERED` in one step.
  - A `MESSAGE_SENT` event is the queued item itself.
  - The outbox marks each event delivered before it awaits the callback (events.py:69-71).
- `asyncio.Semaphore()` stands in for `asyncio.Lock`, which lint TID251/S039 bans. Its default value is 1, so it is the same mutex, and the local Python 3.11.0 has the gh-90155 cancel fix. Do not switch it back to `Lock`.

**Failure containment**
- Containment matches EC-16 (a), (b) and (c) and EC-38 when driven for real:
  - an exception in `end_turn` or `collect_messages` becomes `AGENT_FAILED` naming its cause;
  - an exception in a tool becomes a tool error the agent reads;
  - `KeyboardInterrupt` and `SystemExit` propagate bare, and the run flag is cleared.
- FAILED is chosen only when no agent is still running.
- A failed agent's mail is excluded from MAX_TURNS (:265).
- `AgentSwarmMember.provider` uses `ModelProvider(...)`, which C012 forces, and `on_event` is checked with `callable()`, which S009 forces. Both are recorded deviations; leave them.

**Scope and boundaries**
- The change stays inside its boundaries:
  - 23 new and 13 modified product files, exactly the §8.4 budget;
  - `lint/baseline.json` is unchanged, and `tests/` has not changed since `87c8ed14`;
  - `runtime.py`, `runtimes/actor/`, `infinite/`, `jev/` and `validation.py` are untouched;
  - `base.py` changes only the `_LINEAR_LOOP_RUNTIMES` entry and its comments;
  - no NG-1 to NG-10 item was built (no backlog, lock, broadcast, `web_fetch`, journal, events file or CLI).
- Placement and layering hold:
  - the enums, records and constants are in `vidbyte/lib/<kind>/agent_swarm.py`, and the enums are exported;
