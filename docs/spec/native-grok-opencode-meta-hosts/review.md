### What the spec requires
INV-13 decides the race, so no spec change is needed:
- An interrupt that loses to the turn's own end raises nothing.
- The turn's recorded terminal state stands.
- `was_running` reports what the host found before it sent anything. EC-52 defines the finished case as one where "Nothing is sent". EC-53 already allows `was_running=True` with a turn that then records COMPLETED, because Grok can answer `end_turn` after the cancel is written.
- So an interrupt the host *sent* to a turn it found running returns `was_running=True`, even when the turn's end beats the interrupt's write or answer and the driver closes the peer for that reason. An interrupt that finds the turn already ended sends nothing and returns `False`.

EC-51 (Grok) and EC-96 / EC-97 (Muse) still raise. Their triggers are peer-side ("the peer has already exited", "the peer exits … or stops accepting stdin", "no answer"), and the peer stopped while the vendor had **not** reported the turn's end. A close that the host's own driver makes after the turn ended is not one of those triggers.

Optional one-sentence clarification for INV-13 (not required): "`was_running` reports what the host found before sending; an interrupt sent to a running turn raises nothing when the turn ends before the interrupt's write or answer completes, and EC-51 and EC-96 apply only when the peer stopped before the turn's end was reported."
