### 2.3 How `catalog.py` resolves a leaf, and what `.md` may contain

`vidbyte/prompts/catalog.py`:

- `_load` (`:108-112`): each JSON leaf id `family.leaf` must name a `Prompt` member, else `ConfigurationError`; duplicates refused.
- `_resolve_prompt_text` (`:166-180`): a string value is inline text; a dict must carry `path` ending in `.md` (`:174-175`) and `source_url` (`:173`); the file is read as `asset.parent.joinpath(path)` in utf-8 text mode via `file.read()` — verbatim: no `strip`, no `format`, no newline normalisation beyond Python's universal newlines (CRLF on a Windows checkout becomes LF). Missing file → `ConfigurationError` (`:177-178`); blank text → `ConfigurationError` (`_validate_prompt_text`, `:182-186`).
- `_validate_enum_sync` (`:188-192`): every `Prompt` member must have an asset. Nothing checks the reverse, and nothing checks for stray `.md` files in the folder that no JSON leaf references.
- What a `.md` may contain: headings, bullets, backticks, and Markdown of any kind load fine for all 40 leaves. Literal `{` or `}` are fatal only in the 13 leaves the consumer passes to `str.format` (rows 4-7, 9-16: `KeyError`/`ValueError` at the first call); the 27 raw leaves (rows 1-3, 8, 17-40) tolerate braces, but none contains any today and the fixture `template_regex` treats every `{word}` as a wildcard, so braces in a raw leaf would silently weaken the regex tests. A leaf's text is also JSON-schema `description` text for rows 17-40, so it is sent byte-for-byte inside the tool schema; Markdown there is tolerated by providers but counts toward every call.
