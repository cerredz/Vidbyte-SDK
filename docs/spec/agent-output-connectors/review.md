Diff reviewed: `origin/main..9463c348` (merge base `db3988ff`; worktree HEAD `0b9bc19e` differs only in `pipeline.md`) · Lenses: conformance, conventions, engineering · Verifier: reports/S4-findings-verifier.md

## Verdict
MERGEABLE AFTER FIXES — The design, wiring and test pack are sound, but every HTTP send writes its URL to the `httpx` INFO log (six connectors keep the credential in the URL). Three Majors also remain: a caller connector with a non-enum `destination` breaks delivery after the run; sync `run()` with email is not bounded by the delivery deadline; and the email-address rule is copied into two modules. All four fixes are small and local, and none touches `base.py`.

## What the implementation gets right (so nobody "fixes" it)
- **The §4 snippet runs exactly as written.** It was extracted from spec.md and executed verbatim, with only the model runner and `_send_once` scripted. It prints `slack sent None\ngithub_issue sent https://github.com/acme/shop/issues/412\n`, byte-equal to §4. Slack gets `"<title>\n\n<body>"`; GitHub gets `{title, body, labels:["bug"]}`.
- **The `base.py` hook matches r5 exactly.**
  - `if self.outputs:` guards the call, so an agent without outputs adds no await (INV-22).
  - `_deliver_outputs` catches `BaseException`, clears the context-var-scoped `_queued_prompts`, notifies the session, and re-raises (INV-7, INV-20).
  - `_generate_reply` stays at C901 10 / PLR0912 9 / PLR0915 50, identical to `db3988ff`. None of R-1..R-4 needs to touch `base.py`.
  - `FailureRouter.capture_exception` deduplicates by exception identity (`sessions/failure/router.py:378-384`), so AC-23 records the error once.
- **`OutputDispatcher.deliver` is a model narrated main function. Do not "simplify" it or `_deliver_outputs`.**
  - It runs `gather(return_exceptions=True)` and re-raises non-`Exception` BaseExceptions, so cancellation propagates.
  - It pairs results with `zip(strict=True)` and raises `OutputDeliveryError … from first_exception`.
  - The deadline is read from the module global at call time (`dispatcher.py:92`), so the deadline test is meaningful.
- **Placement and layering follow Prompt 4 and AGENTS.md.**
  - The Protocol, `OutputShaping` and `OutputDispatcher` live in `vidbyte/agents/output/`, and all provider work lives in `vidbyte/lib/outputs/`.
  - Enums, records and constants are in their `lib/enums`, `lib/dataclasses` and `lib/constants` modules, and the Jev capability is a validated `JevAgentSettings.outputs` field.
  - No lib module imports a higher layer. `agents/output` imports only the stdlib, `vidbyte.lib.*` and itself.
  - No OAuth, MCP, CLI, YAML or keyring code was added, and `pyproject.toml` is unchanged.
