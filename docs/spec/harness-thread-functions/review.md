## What the implementation gets right (so nobody "fixes" it)
- The public surface is exactly the contract. `vidbyte.harnesses.native.__all__` holds the nine coroutines plus the D-22 names (17 entries), and each subpackage's `__all__` holds its three functions. The old names are gone. `vidbyte/tools`, `vidbyte/lib/configs`, root `vidbyte/__init__.py`, `lint/` and `pyproject.toml` are byte-identical to `origin/main` (the merge base `179d8adc`). The old spec folder is deleted, and nothing refers to `NativeHostError`, `ManagedProcess`, `GrokHost` or `native_hosts`.
- Key isolation follows INV-3 and D-6 on every harness. Grok gets `GROK_HOME=~/.vidbyte/grok-homes/<sha256(normcase(resolved ws))[:16]>` (`grok/threads.py:141-143`). opencode gets an inline `provider.<prefix>.options.apiKey` (`opencode/wire.py:44-49`). Muse gets `META_API_KEY`, a per-call `XDG_CONFIG_HOME` and a `MUSE_AUTH_PATH` that never exists, while serve runs with `env_remove=(META_API_KEY,)`. `MuseLauncher.environment` forwards only the overlay names through `WSLENV`, after the caller's own entries (`muse/launcher.py:96-109`). Do not "simplify" any of these.
- The key reaches a child only through the environment overlay. `CliInvocation.env_overlay`/`stdin_text` and `NativeThreadRequest.api_key` are `repr=False`, and the validator never quotes `api_key`. `NativeErrorFactory.scrub` replaces registered secrets before the redactor and before its own 1,000-character cap, and the AC-4 echo test passes.
- INV-15 holds mechanically. No module under `vidbyte/harnesses/native/` holds a module-level constant or a fixed literal, and all 198 constants in `vidbyte/lib/constants/native_threads.py` have a reader. Every vendor argv goes through `CliArgv.build` with enum flags: JOINED for Grok and opencode, SEPARATE for Muse exec and serve, `wsl.exe -l -q` and the reap. The one exception is R-2's `-s`.
- Placement follows AGENTS.md. Records are in `vidbyte/lib/dataclasses/{native_threads,process,validation}.py`, and enums are in `vidbyte/lib/enums/{native_threads,process}.py`, all exported from `vidbyte/lib/enums/__init__.py`. The 28 `FailureCode` members follow `RULE_EVALUATION_FAILED`, and each has its own likely cause and next step in the closed `NATIVE_THREAD_FAILURE_CODES` table. `NativeThreadError` keeps the literal 8-name `DIAGNOSTIC_FIELDS` (A003).
- Each public function has one guarded try. `CancelledError` and `NativeThreadError` are re-raised, `ConfigurationError` becomes `configuration.invalid_argument`, and anything else becomes `runtime.error`, named by its class only. Every code comes from the closed table.
- The prompt never reaches an interpreter. `CliArgv` puts it inside `--single=`, after `--`, or on stdin, and batch launchers are refused on win32. The runner gives POSIX children a new session plus `killpg`, and runs Windows `taskkill /T` with a leader-kill fallback. Each stream has its own byte cap with a truncation probe. taskkill finishes in about 0.1 s, so the 1 s kill wait is enough.
- The budget is met exactly: 24 added `.py` files, and 45 added classes (17 new + 16 kept + 12 new enums). The test tree only adds files (18), and there are no suppressions or baseline edits. Every new file has an A001 header, each §12.4 policy point has an `# @intent` block, and each `execute` is narrated step by step. The spec §4 snippet runs green against stand-ins. Lint passes, and seven rule counts improved without a rebaseline.
