# Test plan: Harness thread functions

Spec: `docs/spec/harness-thread-functions/spec.md` r3 · Framework: pytest 8.3.5 + pytest-asyncio 1.3.0 · Prior art copied: `tests/features/grok_host/conftest.py` (`GrokFake`), `tests/features/muse_host/conftest.py` (`MuseFake.build_wsl`)

Pack: `tests/features/harness_threads/` (397 tests in 14 files after the r4 additions; `NativeThreadError.relevant_tests == ("tests/features/harness_threads",)`). The 49 files of the rejected design's packs (`grok_host`, `opencode_host`, `muse_host`, `native_backends`) are deleted; none of them exists on `origin/main`. No test file that exists on `origin/main` was touched.

All vendor programs are `fake_harness.py` (stdlib only), reached through `<harness>_command` or as `.exe`/script stand-ins on a PATH that holds only the sandbox's own folder; the user home and the temp folder are redirected into the sandbox. Seams used are the ones spec §13 lists: the `<harness>_command` fields, PATH, `USERPROFILE`/`HOME`, `tempfile.tempdir`, and the three timing knobs in `vidbyte.lib.constants.native_threads`. `CliRunner.run` is wrapped (never replaced) by a recording spy in two tests, and replaced by a raising function in one (EC-32).

## Notes for the implementer
- Pack name: `tests/features/harness_threads`, so `NativeThreadError.relevant_tests == ("tests/features/harness_threads",)` and `related_docs == ("vidbyte/harnesses/README.md",)`; `test_error_class_carries_the_diagnostic_packet_for_this_feature` checks that both paths exist.
- Every vidbyte import in the pack is lazy (inside the `lib_api`/`api` fixtures), so the pack turns green in phases: records, argv and runner tests need only the `vidbyte.lib` modules.
- The three timing knobs (`NATIVE_KILL_WAIT_SECONDS`, `NATIVE_CONTROL_TIMEOUT_SECONDS`, `MUSE_REAP_TIMEOUT_SECONDS`) are monkeypatched on `vidbyte.lib.constants.native_threads`; read them through the module object at call time. Output caps (`GROK_CLI_MAX_OUTPUT_BYTES`, `NATIVE_PROCESS_MAX_OUTPUT_BYTES`) and `NATIVE_RESULT_TEXT_MAX_CHARS` are read from the module but never patched; the cap tests write just past the real values.
- Seams the tests rely on: `Path.home()` (tests set `USERPROFILE` and `HOME`); `shutil.which`-style PATH lookup honouring `PATHEXT` (stand-ins are `grok.exe`, `opencode.exe`, `wsl.exe` on win32); `tempfile.mkdtemp()` with no `dir` (tests set `tempfile.tempdir`, and assert the folder is empty after each Muse call); the `wsl.exe` PATH check for WSL mode.
- `check_error` (conftest.py) is the INV-5 contract: the message must contain, in order, the function name, the code value, the label ("Grok Build", "opencode", "Muse Code"), the resolved workspace (native or POSIX spelling), the thread id when known, the observation, the scrubbed vendor text, the likely cause and the next step, with at least three sentence ends. Observations the tests look for: seconds as `str(timeout)` (`1.5`), the byte cap as `str(cap)` or `f"{cap:,}"`, `str(exit_code)`, the missing member name (`sessionId`, `sessionID`), the program/PATH/fallback path for not_installed, the refused path for batch launchers, the private home for an unpreparable home, the launch failure kind value (`os_error`, `permission_denied`), the exception class for runtime.error, and both distro names for an unknown distro. Matching is case-insensitive on win32 only.
- `OPENCODE_CONFIG_CONTENT` is compared exactly: `{"provider": {"<p>": {"options": {"apiKey": key}}}}`, plus `"skills": {"paths": [...]}` only when skills are passed (§9.2's bracket). Paths are the resolved folders, in the caller's order.
- The Grok stand-in stores threads under `GROK_HOME/sessions/<sha256(normcase(abspath(--cwd)))[:16]>`, so `--cwd` must be the resolved workspace and the same `GROK_HOME` must be used per workspace. The SDK itself may write only `skills/` in the private home (`sessions/` is the stand-in's).
- Grok continue: the stand-in can answer the id in upper case (`continue_upper_id`); the result must carry the caller's id. A continue answered on another id is `<h>.thread_not_found`; a fork answering its source is `<h>.protocol_mismatch` (Grok, opencode).
- Muse serve: frames are `initialize` (id 1, non-empty `clientInfo.name`/`version`), the `initialized` notification without id, then the request with id 2, then EOF. `session/read` params are exactly `{"sessionId", "excludeItems": true}`; `session/fork` adds a UUIDv7 `commandId`. Serve's stdin must be a pipe; exec's must not.
- Stand-in exit codes: failures exit 93 (so the exit status cannot collide with other digits); key rejections exit 1. Vendor texts the classification must recognise are in `fake_harness.py` (`GROK_NOT_SIGNED_IN`, `MUSE_KEY_REJECTED`, opencode `ProviderAuthError` and `statusCode` 401, `Session not found`, WSL `WSL_E_DISTRO_NOT_FOUND`, `execvpe(...) failed: No such file or directory`).
- WSL mode (win32): the `wsl.exe` stand-in forwards only the names `WSLENV` lists; the exec must see `META_API_KEY`, `MUSE_NO_AUTO_UPDATE`, `XDG_CONFIG_HOME` and `MUSE_AUTH_PATH` (both `/mnt/...`), and `VIDBYTE_PEER_MARK` (`^[0-9a-f]{32}$`, fresh per call). `WSLENV` must start with the caller's own value; the five names (exec) or four names without `META_API_KEY` (serve) follow in any order. Serve must not forward `META_API_KEY`, even when the caller's environment holds one. The reap is `wsl.exe -d <distro> -e sh -s <mark>` with the script on stdin (no `\r`), after any timeout (exec or serve) and on cancellation, before `CancelledError` propagates.
- AC-16 "not rebuilt" is checked with a hard link from outside the private home to `skills/<name>/SKILL.md`; leave matching folders untouched (do not remove-and-copy when the content already matches).
- Line endings: `git config core.autocrlf=true` here, so test files are CRLF in the working tree and LF in blobs; the INV-21 test compares with `git diff --name-only` (autocrlf-safe) and also fails on untracked files under the scoped folders.
- The old packs (49 files) are deleted; S3 must not recreate them or touch any test file.
- (r4) Native Muse serve must get no `META_API_KEY` even when the caller's own environment holds one: pass `env_remove=(META_API_KEY,)` on the serve `CliInvocation` and let `CliRunner` drop it before adding the overlay (`test_muse_serve_never_sees_a_key_even_the_callers_own`, `test_env_remove_drops_an_inherited_name_before_the_overlay`).
- (S4, R-4) The program lookup must walk only the absolute `PATH` entries with `PATHEXT`; Python 3.11's `shutil.which` on win32 puts the current folder first even when `path=` is given. The launcher tests `chdir` into the workspace and plant decoys there.
- (S4, R-6) The stand-in's `stderr_text` scenario field writes that text to stderr before any mode runs; a timed-out or capped run must hand its stderr to the error as vendor text.
- (S4, R-10) The cancel-during-preparation test holds the Muse skill copy at `os.makedirs` (the call `copytree` makes for the copied folder) and releases it right after cancelling; the temp folder must be gone when `CancelledError` reaches the test, so the cancellation path has to wait for the copy, then remove the folder.
- (S4, R-11) Both leader-exit tests end the grandchild themselves; the run must return within 4 kill waits plus slack of the leader's exit, with the leader's output and exit code 0.
- (Re-review, R-27) The cancel test reads `NATIVE_KILL_WAIT_SECONDS` through the constants module (patched to 5 s) and checks that no task started since the run began is unfinished 1 s after `CancelledError`; the reader tasks must be stopped or finished on the cancel path.
- (Re-review, R-28) Start taskkill by an absolute path. The tree-stop tests run with `PATH` set to the sandbox's empty bin folder, so a lookup on `PATH` would lose the tree stop there.
- (Re-review, R-29) The dense-prompt refusal must name the value of `NATIVE_WINDOWS_ARGV_PROMPT_MAX_UNITS` (a module constant, read at test time) and say "command line", in that order; the 24,000-character cap stays for the plain length check.
- (Re-review, R-30) The double-cancel test opens the hold before it awaits the call, then polls up to 5 s for the temp folder to go; the removal must survive the second cancel.
- (r4) EC-45: a Muse `session/fork` answer equal to the source id is `muse.protocol_mismatch` with `thread_id` = the source id and no exec; a Muse exec whose first session stream differs from the id sent with `--session-id` is `muse.thread_not_found` with `thread_id` = the stream id the stand-in answered (the stand-in's `mode=continue_other_id`).
