## Tests deliberately NOT written
| Candidate | Why it would not earn its keep |
|---|---|
| Property-based fuzzing of the key pattern and the retry rule (`hypothesis`) | `hypothesis` is not installed, and NFR-6 forbids a new dependency. The domains are small: the key rule is pinned by boundary rows (31 vs 32 characters, every character class, the injection string) and the retry rule by every listed status. |
| Agent-runtime retries reusing a key (EC-14 runtime half, NG-9, Q-1 = No), and Q-8..Q-11 controls | Out of scope by the briefing and the spec. Nothing to build or test. |

| EC-34 `KeyboardInterrupt` | It goes through the same `except Exception` boundary as `CancelledError`, which is tested. Raising `KeyboardInterrupt` inside `asyncio.run` triggers the interpreter's SIGINT handling, which makes the test fragile on Windows. |
| EC-22, INV-23 (agent key-crossing guards) | The code is unchanged (AC-19 forbids touching `vidbyte/agents/`), and the existing agent tests cover the guards. A managed child is the same runner path as AC-24. |
| EC-23 (grader ignores `VIDBYTE_API_KEY`) | The code is unchanged (NG-11), and a test would only restate today's behavior without discriminating anything this change adds. |
| EC-31, EC-39, T-7 (provider-side state, replay outage) | Server-side or accepted limitations. The SDK only forwards `cachedContent`, which the AC-26 test already sends. |
| EC-35 (outer timeouts below 630 s) | Lives outside `vidbyte/lib/`. The README fact is in AC-18's scope, and asserting the "120 s" sentence would pin wording. |
| INV-15 (no markup constant) | The AC-1/AC-2 envelope checks already fail on any added price or fee field. A grep for `0.02` would be a brittle lint, not a behavior test. |
| R-10 (`VidbyteGatewayTransport` not re-exported from `vidbyte.lib.http`) | A failure would not change anything a caller sees. |
| C017/C018/C019/C020 counts | Enforced by `python lint/run.py` inside `python scripts/run_ci.py` (AC-17). Duplicating them in pytest would add a second, drifting source of truth. |
| Real `asyncio.sleep` timing for the 0.5 s / 1.0 s waits | The waits are asserted as the values passed to `asyncio.sleep`. Measuring wall-clock time would make the tests slow and flaky. |

## Notes for the implementer
- **Names the tests import, exactly as in §8.5:**
  - `vidbyte.lib.config.TextModelMode`, which must be the same object as `vidbyte.lib.enums.TextModelMode`;
  - `TextModelConfig.mode` (last field), `.is_vidbyte_managed()`, `.resolved_api_key()` (returns the placeholder when managed);
  - `ProviderModelRegistry.resolve_vidbyte_api_key`;
  - the constants `VIDBYTE_MANAGED_KEY_PLACEHOLDER`, `VIDBYTE_MANAGED_DEFAULT_MAX_OUTPUT_TOKENS` and `VIDBYTE_GATEWAY_TIMEOUT_FLOOR_SECONDS` in `vidbyte.lib.constants.jev`.
- **Seams:**
  - The runner's default transport is looked up as `vidbyte.lib.runners.text.HttpTransport`.
  - The retry wait is patched at `vidbyte.lib.http.vidbyte_gateway.asyncio.sleep`, so the module must `import asyncio` and call `asyncio.sleep(...)`. `from asyncio import sleep` breaks every retry test.
  - Call `inner.request(...)` with keywords `method`, `url`, `headers`, `json_body`, `timeout_seconds` and `idempotency_key`. Leave `retry_count` out, or pass 0.
- **Messages the tests check** (everything else is free wording):
  - Every `provider="vidbyte"` error names the managed provider value (for example `openai`) and, when a status exists, the status number (INV-11).
  - The endpoint refusal contains the word `endpoint`.
  - The unmanaged-provider refusal contains all six lowercase provider values.
  - The streaming refusal contains `managed`, `TextModelRunner` and `<PROVIDER>_API_KEY`, with `details["mode"] == "vidbyte_managed"`.
  - The row-5 remedy keywords are listed in `test_gateway_error_messages_state_the_remedy_section_9_2_binds_for_each_status`.
  - Row 1 must mention no response, billing and the timeout (630).
  - Row 3 must mention the edge, the retry and "transient".
  - Row 6 must say "withheld" and not billed.
- **README:** a level-2 to level-4 heading containing "Vidbyte-managed" (or "Vidbyte managed"). Its section must contain:
  - `2%`, `VIDBYTE_API_KEY`, `Idempotency-Key`, `maxOutputTokens`, `max_output_tokens`, `previous_response_id`, `2,000,000`, `8,192`, `630`;
  - the six provider names;
  - "stream", "service tier" and "snake_case".
- **No body text in errors:** never put gateway or provider body text, the gateway `code`, or an exception's text into a message. The tests scan the formatted traceback, so raise after the `except` block has ended (D-17).
- **Fixtures:** do not change `managed_text_fixtures.py` to make a test pass. Its bodies deliberately carry `BODY_CANARY` and `LEAKED_KEY`.
- **Run commands:**
  - Run the pack with `PYTHONPATH=$(pwd) python -m pytest tests/features/sdk_managed_text`.
  - The test modules import `tests.features.sdk_managed_text.managed_text_fixtures`. That works under `python -m pytest` from the repository root, which is how `scripts/run_ci.py` runs it: the working directory is on `sys.path`, and `tests/__init__.py` exists.
