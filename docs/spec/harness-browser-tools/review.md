## What the implementation gets right (so nobody "fixes" it)
- **One call path, every layer (INV-1, §5).** All nine `_call`s build `NativeThreadRequest` and `BrowserToolRequest` and hand a `<H>BrowserHarness` to the single `NativeBrowserRun.execute`. It runs the §5 order exactly: register the keys, `select`, `check`, `prepare` (Node only for stdio, Chrome only for `needs_chrome`, then the cache, then `mkdtemp`), `run`, `tool_calls`, `require`, `complete`. Any failure gets a shielded `discard`. No harness can skip a layer.
- **AC-1 is real, and the signatures match.** The acceptance `SNIPPET` is byte-identical to spec §4, with only the workspace literals replaced, and it passes offline. All nine signatures equal their plain siblings plus keyword-only `tools` and `tool_keys` after `model` (INV-2, FR-2). Native `__all__` has 28 names; each subpackage has 6.
- **The plain paths are byte-identical (INV-14, INV-16).** Every new branch is gated on `mount is None` and keeps the original values: Grok `json` output, the 4 MiB cap and `env_remove=()`; Muse `settings=None` and `web_tools_off=False`; opencode `config_content(request, None)`. The plain `_call`s return `.result`. Pre-existing test diffs only re-pin the values §13 lists, and the `expected` texts are unchanged through `NATIVE_THREAD_RESULT_RECORDS`.
- **The budget and the Never list hold.** There are 12 new files and 34 classes, no file outside §12.3, 0 new dependencies, 0 config keys, `lint/baseline.json` unchanged, no suppressions, and no `npx`, `@latest` or approve-all. CI on `d00bd8ba` is green (runs 39075450892 and 39075452414), and `SDK-LINT: PASS` with no rule above baseline.
- **Errors conform (D-29, D-22, D-15).** Each `browser.*` code has one cause and one next step, with situation detail in the observation. Every factory path routes through `_error`, so all 18 operations get the right result record. The D-22 widened texts are present.
- **Placement and layering.** The 7 StrEnums are in `lib/enums/browser_tools.py`, the 9 frozen slotted records in `lib/dataclasses/browser_tools.py`, and the constants, registry and reaper under `lib/`. Every enum and `NativeThreadResultRecord` is exported from `lib/enums/__init__.py`. D-27 import direction holds: `hostkit/browser.py` imports the concrete `hostkit.errors` and `hostkit.skills`, and `mounts.py` imports nothing from its subpackage (A006 34/34).
- **Validation never quotes caller text (KD-6, D-28).** `BrowserToolRequest` checks with `accepts_text` and constant messages. Odd inputs (a non-list `tools`, too many items, a list as `tool_keys`, non-str keys or values, an iterator) all raise `ConfigurationError` without quoting.
- **Key hygiene.** Keys are registered before `select`. Every `from exc` chain wraps a path-only `OSError` or `RuntimeError`, a constant `ConfigurationError`, or a scrubbed `NativeThreadError`. `tool_keys`, `selection.key` and `env_overlay` are `repr=False`. `os.environ` is never changed. The only direct writes are the Grok agent file and Muse's `settings.json`, each in its per-call folder.
- **The reaper is narrow and bounded.** On Windows it runs System32 PowerShell by absolute path. The marker travels only in `VIDBYTE_REAP_MARKER`, it matches with `IndexOf(..., OrdinalIgnoreCase)`, and it skips `$PID`. On POSIX it runs `ps` from `NATIVE_PS_PATHS`, never PATH, and skips its own pid. It never raises, and it counts only the processes it stopped. Fixed-length `mkdtemp` markers cannot be substrings of one another.
- **Cleanup runs however the call ends after `prepare`.** `complete` sits inside the same `try`, so a failure there still reaches `discard`. `discard` cannot raise, so the original `NativeThreadError` or `CancelledError` propagates (INV-6).
- **Partial failure is handled for opencode, Muse and Grok's cancelled turn.** opencode compiles a fail-closed permission order (wildcard deny, then exact allows; webfetch and websearch denied) with `vidbyte-` prefixed, `enabled: true` ids. A Grok `cancelled` stopReason becomes `grok.run_failed`. Muse's "Required MCP server" failure becomes `browser.tools_unavailable`, and its settings are compiled only into the verified `schema_version` plus `mcpServers` shape.
- **Stated limits are honest.** The README lists each harness's mount limits. `BROWSER_MUSE_WSL_DETAIL` names the keyless remote tools, and `BROWSER_GROK_BUDGET_DETAIL` tells the caller to narrow capabilities. §17 deviations 1, 2, 8, 9, 11 and 13–16 match the code.
- **Docs and hygiene.** The largest new file is 400 lines, and `execute`, `select` and the stream readers are narrated with `@intent` blocks. All implementation commits have conventional titles that carry spec IDs, and no `.pyc`, `__pycache__` or `egg-info` file is tracked.
