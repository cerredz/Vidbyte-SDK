# Test plan: AgentSwarm v2 (agents with one shared prompt, loose messaging, per-agent compaction, a hook-derived event log)

Spec: docs/spec/agent-swarm-v2/spec.md r3 · Framework: pytest 8.3.5 + pytest-asyncio 1.3.0 · Prior art copied: the r5 pack itself (`tests/features/agent_swarm/` at `06861b41`: `ScriptedSwarm` at `BaseAgent._runner_for_model`, `EventLog`/`Signal`/`Gate`, the `_Replay` event oracle, `guard_asyncio_run`, `assert_no_stray_tasks`); the r5 deliberate fault (monkeypatched `AgentSwarmRuntime.record_tool_call`) for AC-24; `MessageHistoryCompactionMiddleware.trim_with_provider_boundaries` transform metadata (`vidbyte/middleware/compaction/context_compaction.py`) for AC-11; `TavilyClient.search` as the only network seam for web search (`vidbyte/tools/builtins/operations/clients/tavily.py`); `BaseAgent._runtime_middleware` as the place to append a one-shot retry (`RetryModelErrorOnce`) for AC-10; `vidbyte/tools/builtins/bash.py` module globals `BASH_TIMEOUT_SECONDS` / `BASH_MAX_OUTPUT_BYTES`, read at call time, for AC-14.

**Pack:** 10 test modules, 268 collected cases (r5 had 171). New modules: `test_agent_swarm_settings.py` (11), `test_agent_swarm_stop.py` (8), `test_agent_swarm_observer.py` (7), `test_agent_swarm_compaction.py` (12). Rewritten in place: `FEATURE.md`, `agent_swarm_fixtures.py`, and the six r5 modules. Nothing was deleted, skipped, or loosened; every renamed r5 test is listed with its spec ID in the S2 report.

**Oracle:** every run test ends with `assert_event_invariants(result, names, max_turns=..., log=...)`. It replays `result.events` as the spec's state machine for all 24 kinds: INV-7 (one outcome per message), INV-9/10 (wake or `wake_refused` right after a send or a turn end with mail), INV-12 (one `swarm_stopping`, in the deciding block, followed by every queued message's `message_undelivered` in member order), INV-13 (nothing wakes or is delivered after the stop), INV-14 (exactly one terminal per agent; a failed or exited agent's inbox is undelivered next; `agent_released` only after the stop; no release on timeout), INV-16 (1..N, one last `swarm_ended`), INV-17/28 (`workplace_prepared`, then `agent_created` × N, then `agent_started` × N), INV-21 (each kind sets only its `_KIND_FIELDS`), INV-25..27 (a derived event follows its own agent's matching `tool_called`; `file_changed` peer = previous different writer), INV-20 (one callback at a time; on_event saw exactly `result.events`), and the replies rule (released agents in member order; on QUIET/MAX_TURNS each reply is that agent's last `agent_idle` text). `ScriptedSwarm.assert_complete()` then fails a run whose script was one step short or long, or whose runner saw an unscripted call.

## Tests deliberately NOT written

| Spec ID | Why not | What covers the risk instead |
|---|---|---|
| EC-13 | §13: with the member's `AgentLoopSettings` no `tool_loop_limit` or `max_iterations` stop is reachable offline without changing the loop (NG-1). | AC-24 pins the `agent_exited` branch through `middleware_abort`, the same `_early_exit` path with another stop value. |
| EC-26 | The stale-value case is impossible by construction (every iteration starts with a model call); there is no state to set up. | AC-17 rows read the value from the call just made. |
| EC-27 | The case cannot be reached while the shipped constants hold (S4 R-12). The engine does not guarantee it: at `keep_last=0`, `SummarizeRangeCompaction` keeps nothing (`vidbyte/middleware/compaction/strategies.py:351-356`). The at-least-one guarantee is `AgentSwarmMemberRuntime._keep_last`'s `max(kept, 1)` in `member.py`, which the strategy then rounds up to the newest whole group. That floor matters only when the newest message alone is over the target. The newest message at the compaction seam is always one tool result, because mail is appended after the compaction, and a single result over the target cannot occur while the 100,000-character result cap (about 25,000 tokens) is below the 27,000-token target. The S4 verifier found the `keep_last_zero` mutant equivalent for this reason. | AC-16 asserts the kept groups verbatim; AC-11 pins the trim. If the result cap or the target changes so that one result can exceed the target, write the swarm-level EC-27 case. |
| EC-29 | 500 scripted members × 500 turns is a load test, not a behavior test; the rule is INV-9 with N members. | Property tests under a tight turn budget (2–4 agents); AC-20 accepts 500 members. |
| EC-30 | Back-pressure from 500 concurrent flushes cannot be observed deterministically without timing. | Outbox tests (`test_the_event_outbox_delivers_each_event_once_in_order_even_with_concurrent_flushes`, slow and raising callbacks). |
| EC-31 (the run side) | A thirty-day run cannot be exercised; only the setting can. | AC-20 accepts `2_592_000.0`. |
