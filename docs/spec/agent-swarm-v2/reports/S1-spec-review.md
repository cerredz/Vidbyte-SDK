# S1 spec review — agent-swarm-v2 spec r1 (`57c20f68`), worktree HEAD `febfa041`, product code at `39ce8b20`

VERDICT: SOUND WITH FIXES — the architecture (await-free state blocks, budget stop through the two middleware abort paths, compaction on the engine at the `_after_tool_iteration` seam, settings in lib with every field type resolvable inside `vidbyte.lib`) is right and verified against the code; one invariant is contradicted by the design as written (a message can get two outcomes after the stop is decided), one edge case is described backwards (a timeout during the start flush leaves no member task to record a terminal event), one trigger reads the wrong usage accessor on Anthropic, and the §12 contract disagrees with itself on tool order and on phase P1.

WHAT THE SPEC GETS RIGHT

- The stop decision is one block (`_stop`) reached from `_end_check`, `record_model_call`, and the post-group timeout, and every new runtime-decision event is recorded in the same synchronous block as the branch it describes; this keeps r5's concurrency argument intact (`vidbyte/agents/agent_swarm/runtime.py:160-191,201-233,271-291` all already follow that shape).
- Budget enforcement through middleware is sound: both `before_model_call` (`vidbyte/agents/runtime.py:728-742`) and `after_model_response` (`:488-503`) return `_middleware_abort_result` (`:1204`, stop reason `middleware_abort`) without touching the loop, and `_finish_result` (`:945`) runs only `after_run`, so no abort ever reaches `end_turn`; classifying a post-decision return as `agent_released` is the right reading of that path.
- The compaction design reuses exactly what exists: `compact_provider_messages(messages, *, mode, options)` (`vidbyte/middleware/compaction/engine.py:57-68`) repairs pairing before computing stats, `SummarizeRangeCompaction` rounds `keep_last` up to whole groups and returns the list unchanged with no middle (`strategies.py:334-366`), the summary converts to a plain `{"role": "assistant", "content": ...}` dict with no `kind` key leaking (`engine.py:_context_message_to_provider`), and the side call through `_runner_for_model`/`_invoke_runner` (`vidbyte/agents/base.py:1661,1519`) is exactly the seam `ScriptedSwarm.install()` patches (`tests/features/agent_swarm/agent_swarm_fixtures.py:276-281`).
- The settings move is lib-clean as specified: `ProviderKeys` (`vidbyte/lib/dataclasses/agents.py:211`), `ProviderKeyMatcher` (`vidbyte/lib/registries/provider_keys.py:32`), the new enum, and the constants all live under `vidbyte.lib`; the precedent `CodingAgentSettings` (`vidbyte/lib/dataclasses/coding.py:38-58`, header rule 4) is real; and the field guide itself places `<Agent>Settings` in `vidbyte/lib/dataclasses/<agent>.py` (`strict-config-dataclasses.md:13`), which D-1 can cite to soften the AGENTS.md exception-1 tension. The `AgentSwarmTrimMiddleware` subclass is the only exact source of `history_trimmed`: `_apply_transform` drops transform metadata (`vidbyte/middleware/pipeline.py:170-186`) and `changed` is computed at `context_compaction.py:226-228`, so the user's count heuristic would misread a compaction as a trim.
