- `claims.py` (`ClaimsSupportedQuestion`, `CLAIMS_SUPPORTED`): every concrete, checkable assertion in the final answer is extracted; done requires tool-call evidence that supports each assertion, or the answer must say the evidence is missing.
- `completion_evidence.py` (`CompletionEvidenceSupportedQuestion`, `COMPLETION_EVIDENCE_SUPPORTED`): the answer's overall "it is complete" status is itself a claim; done requires that the requested outcomes and the run observations support that whole-task status.
- `problems_resolved.py` (`ProblemsResolvedQuestion`, `PROBLEMS_RESOLVED_FIXED`): every problem observed during the run (a failed command, an error) must be repaired and revalidated; after the repairs the original request itself must still be completed.
- `faithful_scope.py` (`FaithfulScopeQuestion`, `FAITHFUL_SCOPE`): the request's hardest-to-avoid requirement is recorded before work; done requires meeting it without narrowing, mocking, skipping, hard-coding a substitute, or redefining it.
- `negative_coverage.py` (`NegativeCoverageSupportedQuestion`, `NEGATIVE_COVERAGE_SUPPORTED`): a "nothing found / all clear / could not finish" report about a requested inspection target is unsupported unless evidence shows the target was actually examined; zero findings alone prove nothing.
- `self_review.py` (`SelfReviewResolvedQuestion`, `SelfReviewInScopeQuestion`): a strict reviewer's objections are listed before finishing; each is cleared only when evidence meets its resolved-when condition, or the request does not ask for that work.
- `can_simplify.py` (`CanSimplifyQuestion`, `CAN_SIMPLIFY_IMPLEMENTATION`): the implementation may stand only when no meaningful, behavior-preserving simplification is available; the handoff must name one or explain why none is supported.
- `expert_depth.py` (`ExpertDepthHandledQuestion`, `EXPERT_DEPTH_HANDLED`): each deliverable has weak points an expert would handle in depth; done requires evidence that each such point was handled in depth rather than in its quick, shallow form.
- `cumulative_obligations.py` (`CumulativeObligationFulfilledQuestion`, `CumulativeUserTurnReconciledQuestion`): every obligation from every user turn stays active until the user cancels or replaces it; done requires each to be fulfilled in the latest state, and silence or omission never deactivates one.
- `state.py` (`DONE_STATE`): all enabled checks are judged in one request over one shared state (`request`, central fields, per-check sections present only when enabled).
