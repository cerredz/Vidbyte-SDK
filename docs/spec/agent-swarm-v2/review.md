## What the implementation gets right (so nobody "fixes" it)
- **Exactly-once outcomes are structural.** Every runtime state change is one block with no `await`, followed by one flush of the event outbox under the one-slot semaphore. `_stop` decides the reason once (INV-12). `_run_member` ends each agent with exactly one of released, cancelled, failed, or exited (INV-14). Every message gets exactly one outcome (INV-7). `_stop(TIMEOUT)` cancels the tasks that never started, in member order (EC-10). The cancel branch defers its record without flushing, and the final flush delivers it in order. I re-ran the mutants: `fail_keeps_inbox`, `stopped_recipient_queued`, `cancel_state_swap`, `wake_refused_not_recorded_at_turn_end`, `dropped_no_plus_one`, and `trunc_at_cap` are all killed. Do not restructure `_stop`, `_fail`, `_drain`, `end_turn`, or `post_message`; R-1 changes only the three `_end_check()` call lines.
- **No paid loop call after the stop.** The observer refuses `before_model_call` once `stopping` is set, and `after_model_response` records the call and then aborts (`no_post_abort` killed). The budget check is `>=` against `total_tokens`, which includes all four Anthropic buckets (`budget_gt`, `budget_ignores_total`, `measure_input_not_prompt` killed). The summary call is counted once against the budget (`side_call_not_budgeted` killed). The one gap is the compaction stop guard, which is untested (R-7).
- **Loose messaging matches D-4 and INV-6.** Only blank text and an unknown name are refused, each recorded as `message_refused`. The `validate_call` override is the smallest way to stop the loop's own required-parameter check from preempting those refusals. A self-message is queued. A message to a stopped recipient, or one sent after the stop, is a success reply, recorded as `message_sent` plus `message_undelivered` in the same block.
- **Compaction is built on the SDK engine.** It runs in `_after_tool_iteration`, before mail is appended, through `ContextCompactionEngine.compact_provider_messages(SUMMARIZE_RANGE, keep_last)`. The trigger reads `total_prompt_tokens` against 72,000; the target is 27,000. The side call is metered once (UsageTracker, `tokens_used`, the budget, and `model_called`, in EC-6 order). Gemini's `total_prompt_tokens` is `promptTokenCount`, so the trigger fires for Gemini. Only the size estimate is wrong (R-2). The Gemini adapter turns the engine's summary message into a valid request (verifier probe).
- **Settled decisions are honored exactly.** `AgentSwarmSettings` lives in `vidbyte/lib/dataclasses/agent_swarm.py` and imports nothing from a higher layer. Web search is a validated provider table. The limits are exact to §11. All 24 event kinds have a per-kind field table, and `AgentSwarmResult` checks for exactly one `swarm_stopping`. All 23 leaves meet their sentence counts, and the prompt enum header's "162 … 36 families" matches the members.
- **Layering and placement hold.** Records, enums (exported from `vidbyte/lib/enums/__init__.py`), and constants sit where the Placement Rules say. A006 is clean. The swarm middleware imports the runtime only under `TYPE_CHECKING` and is not re-exported.
- **The shared loop is untouched.** `git diff 39ce8b20...936e3278 -- vidbyte/agents/runtime.py vidbyte/agents/base.py vidbyte/lib/dataclasses/validation.py` is empty (NFR-1, NG-1).
- **Docs and contracts stay in step.** The package README's File Index lists `compaction.py` and drops `settings.py`. The READMEs are under A009 (12,253 / 33,476 / 33,831 characters). The public-API `--check` is current (650 exports). Every feature commit cites W-/FR-/AC- IDs, and no `__pycache__` is tracked.
