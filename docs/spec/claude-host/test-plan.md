# Test plan: ClaudeHost — small atomic Claude Code functions with one agent tool per function

Spec: `docs/spec/claude-host/spec.md` r3 · Framework: pytest 8.3.5 with pytest-asyncio 1.3.0, tests written as `unittest.IsolatedAsyncioTestCase` / `unittest.TestCase`, Python 3.11.0 · Prior art copied: `tests/test_codex_tools.py` (the `mock.patch.object(<loader>, ..., return_value=<fake types>)` seam and the missing-extra assertion), `tests/features/coding_agent/` (feature-pack layout, `FEATURE.md`), `tests/test_mcp_studio_server.py` (MCP listing), `tests/test_agent_tool_loop.py` (scripted runner for the agent snippet), `tests/test_codex_failure_recovery.py:188-201` (one row per failure code), `tests/test_durable_sessions.py:1380` (`await tool.execute(ToolCall(...))`)

**The pack.** It lives in `tests/features/claude_host/`, with no `__init__.py`:
- 10 test modules with 165 tests;
- `claude_host_fixtures.py`, the fake claude-agent-sdk 0.2.165 and `ClaudeHostCase`;
- `FEATURE.md` and `README.md`.

**Test names.** Below, a test is written `<area>.py → Class::test`, which stands for `tests/features/claude_host/test_claude_host_<area>.py::Class::test`. A bare `Class` means every test in that class.

**Levels.**

| Level | Tests | What it covers |
|---|---|---|
| acceptance | 4 | The §4 snippets, run as written. |
| contract | 22 | Public shapes: names, signatures, enums, records, codes, marker bytes, pyproject, docs. |
| security | 6 | Markers, the bound request, foreign handles. |
| unit | 26 | Pure logic: the translator, the mapper tables, the CLI lookup and version and sign-in rules, record validation, the tool-server helpers. |
| integration | 107 | The real `ClaudeHost`, `ClaudeLiveSession`, registry, `ToolExecutor`, `Tools`, `PermissionPolicy`, `ToolsFormatter` and `asyncio.to_thread` over the fake SDK seam. 23 of these, in `stops.py`, are lifecycle and concurrency tests driven by `asyncio.Event` gates. No test sleeps to let something happen: tests poll a condition with `eventually()`, under a 10 s hang guard. |

## Tests deliberately NOT written

| Candidate | Why it would not earn its keep |
|---|---|
| Real-SDK contract tests behind `skipUnless(find_spec("claude_agent_sdk"))` (§13 marks them optional) | This stage must not install the extra, and the downloaded 0.2.165 source is untrusted and read-only, so these tests would only ever be skipped here and could never be proven red. CI never installs the extra either. The fakes copy the 0.2.165 shapes instead: the `ClaudeAgentOptions` fields and defaults, the error hierarchy, and the message fields. They are worth adding later, in their own optional file, once a venv with the extra exists. |
| Live end-to-end against a real `claude` | NG-10 and NFR-6 rule it out: it needs a login and the network, and it spends the user's plan window. It is manual QA after the PR, running the §4 snippet on a signed-in machine. |
| Property-based or fuzz tests (`hypothesis`) | `hypothesis` is not a dependency, and adding it would be a `pyproject.toml` edit this stage may not make. | Stress, soak, performance and memory tests | No NFR sets a latency, throughput or memory threshold, and per-process memory is unmeasured (Q-8). With nothing to assert, such a test cannot fail for the right reason. |
