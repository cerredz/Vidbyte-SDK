2. **`SkillLoader.__init__(entries: Sequence[SkillEntry | SkillDocument])`** (`vidbyte/agents/skills/loader.py`). Its
   first statement converts the argument and checks it in one inline expression:
   `SkillEntries(entries=tuple(entries) if isinstance(entries, Iterable) and not isinstance(entries, (str, bytes)) else entries).entries`.
   Any collection that is not text becomes a tuple once, in iteration order. Text and non-collections reach the record
   unconverted. The memory comprehension then reads `self.entries`, not the raw argument, so a generator or a
   list the caller later clears still works. The resolver map, `load()`, `documents()`, and `_pending_groups()` are
   byte-identical.

   - repeated names: `{"names": sorted(...)}`, found in one pass with `collections.Counter`, preceded by `# @intent skill-entries-unique-names`.

   Every message names `SkillLoader`, and none contains a value, a token, or a key. The record is in the module
   `__all__` only.

## Tricky parts (where reviewers should look first)

1. **The D-14 expression** (`loader.py`, first statement of `__init__`). It must stay one inline conditional, because a separate boolean loses
   mypy's narrowing. `isinstance(entries, Iterable)` is the ABC check. An object that iterates only through the old `__getitem__`
   protocol is not an `Iterable` instance, so it reaches the record whole and is rejected as `entries_type`. This is consistent with INV-2 ("any iterable"
   means registered iterables), but it is a corner worth knowing.
2. **Memory comes from `self.entries`.** Reading the raw argument there would make a generator load `()` (EC-1). The boundary test covers this.
3. **Check order and shapes.** The element check runs before the name check. For example, `(local pdf, local pdf, None)` gives `{"position": 2, ...}`. The
   `details` dicts are compared whole. The repeated-name message points at `details['names']` instead of listing the names, following INV-3's
   "only through these details keys". The record's first message says "tuple or list" even though the record itself takes only a tuple: it is written for
   `SkillLoader` callers, and only a direct internal call can hand the record a list.
4. **Two copies of the name rule** (NG-10, INV-18). `JevAlignmentSettings._normalized_skills` is untouched. The both-doors sweep (300 seeded
   collections) passes. The Jev door counts positions from 1 and turns strings into documents, which INV-18 excludes on purpose.
5. **Contract provenance.** `source.commit` is `56541481`, the docs commit, which was the last commit before generation. The generator stamps HEAD
   and refuses only while its inputs are dirty. Any repair that touches `vidbyte/__init__.py` (`__all__` or `__version__`) or
   `pyproject.toml` must rerun the generator, commit only if it wrote the file, and run `--check`. Never amend.
6. **Line endings.** The repo uses `core.autocrlf=true`: the index holds LF, and the working copy holds CRLF. Git Bash `sed -i` and Python
   `read_text`/`write_text` silently rewrite a working copy to LF. The committed content is unaffected, but I restored CRLF on every file
   I touched that way. Repair agents should prefer the Edit tool or byte-level edits.
7. **Local semgrep needs a shim.** The shared interpreter has `mcp` 2.3.0. semgrep 1.170.1's CLI imports `mcp.server.fastmcp` at startup and
   crashes before scanning. I did not install anything. Instead, the scan ran through
   `C:/Users/422mi/AppData/Local/Temp/claude/C--Users-422mi-vidbyte-repos/1d2c8a26-e7b8-4bc3-b449-2665a570335d/scratchpad/run_semgrep_without_mcp.py`,
   which stubs only `semgrep.commands.mcp` and then runs the real `scan` and semgrep-core:
   `python -I <launcher> scan --error --config .semgrep/typed-mapping-boundary-policy.yml vidbyte`.
8. **Disk.** C: had about 5.5 GB free after the package stage, less than the briefing's 17 GB. The package stage left an ignored
   `vidbyte_sdk.egg-info/` in the worktree, which I removed. An ignored `.vidbyte_evals.db`, a test artifact, is left in place.
