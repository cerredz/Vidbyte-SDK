The real path: `SkillLoader(entries)` → conversion → `SkillEntries.__post_init__` (the only new step; `ConfigurationError` before any I/O) → `await load()` → `_pending_groups` → `asyncio.gather` over `resolver.resolve(group)`. Then each resolver does its own read:
- inline: no I/O;
- local and skills.sh: `read_capped` in `asyncio.to_thread`;
- GitHub and the vendors: `SkillFetch.get` → `HttpTransport.request`, with no redirects.

Bytes are parsed by `SkillMarkdown.parse`. Every expected failure is a `SkillResolution` with a reason. A crash or a cancellation is re-raised before anything is remembered. Documents and permanent failures go into `memory.setdefault`, and the results come back in input order.

- `vidbyte/agents/skills/fetch.py:89`: a non-2xx answer whose error body is over the cap is `fetch_failed` (transient), not `too_large`. This is existing behavior and correct, but a CLI that reports oversize must match on `reason` only.
