| EC-9, `asyncio.run` inside a running loop | That is asyncio's own `RuntimeError`, raised before the loader runs |
| A performance or O(n) test of the name check | No requirement names a budget; a timing test would be flaky |
| A set passed as `entries` (EC-28) | Same path as the dict-keys case (a non-`Sequence` iterable turned into a tuple); a set's order depends on hash randomization, so the dict case pins the behavior deterministically |
| A frozen or slotted check on `SkillEntries` | Structure, not behavior; review and the A-rules own it |
| An exact count of root `__all__` names | C016's contract diff and NFR-6 review own the surface; the contract tests already pin each new name and that nothing else new is exported where they look |
| A Hypothesis property test | Hypothesis is not installed (no install allowed); the seeded `random.Random` sweep gives the same drift check deterministically |
| A credential-message test for EC-13 (a Vidbyte key as a GitHub token) | Resolver behavior, unchanged and already covered by `tests/features/jev_skills_preload/test_skill_sources_security.py` → `test_vidbyte_key_never_reaches_github`, `test_vidbyte_key_never_reaches_a_vendor` |

- 50 errors at setup: `ImportError: cannot import name 'ConfigurationError' from 'vidbyte'` (33) and `... 'SkillLoader' from 'vidbyte'` (17). Each module's import is guarded, and an autouse fixture raises the stored error, so the rest of the suite still collects.

- 9 failures: each docs rule names its stale phrase or missing word (for example `'only stores them' not in ...`, and the "Public door" bullet is missing).

Beyond the import error: with only the three root names injected by a scratch plugin (never committed), 34 of the 50 behavior cases fail on the behavior itself (DID NOT RAISE, wrong `details`, `load()` returning `()`), the 4 contract cases still error on the missing `SkillEntries`, and 12 pass. Those 12 pin behavior that already holds behind the deep import, reached now through the root: AC-2, AC-7, AC-9, AC-13, the exact-names test, the dict-keys container case, the two empty cases, and the both-doors unique and empty rows. They guard the new validation against over-rejecting and the root door against losing a P0 promise.

Green proof: in a scratch copy of the tree (deleted afterwards), the §12.3 reference change (rows 1, 2, 3, 4 to 10, 12 to 15) made all 67 new cases pass, together with the area suite (`493 passed, 1 skipped`). Ten single bugs applied to that copy one at a time were each caught: memory built from the raw argument, the list stored unconverted, 1-based positions, unsorted names, case-folded names, names checked before elements, an element echoed in the message, text accepted as an iterable, an empty collection rejected, and `SkillLoader` missing from `__all__`.

## Notes for the implementer

- The three `details` shapes are compared as whole dicts: `{"entries_type": ...}`, `{"position": ..., "entry_type": ...}`, `{"names": ...}`, with nothing else in them. Type names are `type(x).__name__` (`NoneType`, `LocalSkill`, `SkillResolution`).
- Every rejection message must contain `SkillLoader`; the element message must also contain `InlineSkill` (row 1(b) check 2), for every element type, not only `str`.
- Check order matters: element check before name check. `(local("pdf"), local("pdf"), None)` must report `position: 2`.
- Build the memory from `self.entries`, not the raw argument; a generator holding a `SkillDocument` is in the tests.
- The tests read `loader.documents()` right after construction, and `vidbyte.__version__` from the module, never from installed metadata.
- The docs tests pin words, not sentences. Each rule's part must exist and keep the required words: the skills README intro paragraph (the first paragraph under the title) must say `SkillLoader` and `package root`; a bullet starting `- **Public door.**` must name `SkillLoader`, `SkillResolution`, `ConfigurationError`, `contracts/sdk-public-api.json`, and `tenant`; `## Notes for agents` stays the README's last `##` heading. In the loader header the ARCHITECTURE NOTE must drop `(per agent)` (row 2(d)'s "(per agent, for JevAgent)" passes) and name `JevAgent`. In `REPO_MAP.md` the `vidbyte/agents/skills/` entry must drop `only consumer`, `for the agent's lifetime`, and `until the first run`.
- The release test reads the README line matching `^pip install vidbyte-sdk==(\S+)$` and the llms.txt phrase "identifies the package as version `...`"; keep those shapes when bumping.
- Run the new folder with `PYTHONPATH=$(pwd) python -m pytest -q tests/features/public_skill_loader`. Do not run `pip install -e` here; the default python's editable install points at the main checkout.
