WHAT THE IMPLEMENTATION GETS RIGHT (max 4 bullets, concrete, so nobody "fixes" what works)

- The key path is tight. The key travels only in `env_overlay` (`claude/threads.py:151`). `register_secret` runs before the child starts (`threads.py:110`). `protocol_mismatch` never copies raw stdout into the error (`wire.py:73`, `wire.py:76` pass no `vendor_text`). Probes confirmed that `<redacted>` replaces the key in the `result` text, in the `errors` list (both copies) and in the stderr of a bare non-zero exit. AC-7's random-key echo test would fail if `register_secret` were dropped, because the echo has no `key=value` form that `HarnessRedactor` could catch.
- The environment strip is correct on Windows. Python upper-cases `os.environ` keys, so `anthropic_auth_token`, `Claude_Config_Dir` and `anthropic_base_url` were all removed. The child saw only `ANTHROPIC_API_KEY`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` and `CLAUDE_CONFIG_DIR` (probe_case). The AC-6 test asserts the exact list of names, so a `"CLAUDE_"` prefix typo that let `CLAUDECODE` through would fail it.
- `ClaudeWire.read` classifies in the INV-7 order with C901 complexity 8 (measured). `isinstance(status, int)` comes before the frozenset lookup, so list and dict statuses are `run_failed`, not a `TypeError` (probed and tested). A continue keeps the caller's id even when Claude's error answer names another session (`wire.py:52`).
- The Grok switch to `NativePrivateFolders.prepare` behaves exactly as before. The helper body matches the deleted `_prepare_home` expression for expression, and all 131 Grok tests pass.

FINDINGS (ranked, most severe first, max 15)

R-E1 [Major] [failure modes / tests] vidbyte/lib/dataclasses/native_threads.py:96 (with vidbyte/lib/process/runner.py:217, :330) — A prompt holding a lone surrogate starts `claude` with the key, then abandons the child, which never gets stdin EOF and is never stopped
  Evidence: `NATIVE_PROMPT_PATTERN = r"[^\x00]+"` (constants:57) accepts `"\ud800"`, so `NativeThreadRequest` passes it. The child is started first. Then `_feed_stdin` runs `stdin_text.encode(...)` inside `contextlib.suppress(BrokenPipeError, ConnectionResetError, OSError)`. `UnicodeEncodeError` is a `ValueError`, so it escapes, and `run()` only handles `TimeoutError` and `CancelledError` (runner.py:225, :231). Probe `python s4eng/probe.py surrogate` (prompt `"hello \ud800 world"`):
    `surrogate: ('NativeThreadError', 'runtime.error') elapsed 0.33 pid 11936 alive right after call True`
    `message: run_claude_thread failed with runtime.error. … An unexpected UnicodeEncodeError was raised inside the SDK …`
    `alive after asyncio.run returned: True` → `killed leftover pid 11936`
  Failure: Lone surrogates are ordinary in Python strings. They come from JSON `\ud83d` halves, emoji cut in UTF-16, or `surrogateescape`-decoded file names and contents. The call reports `runtime.error` ("a defect in the SDK") instead of refusing the argument. Meanwhile a `claude` child that holds the caller's key in its environment keeps running on a pipe that is never closed. No timeout applies and nothing stops its process tree. In a long-running service each such call leaks one process and its two reader tasks. This breaks INV-5 (the argument is checked only after a process starts), INV-9 (the process is not bounded by `timeout_seconds` and its tree is not stopped) and the "exactly once, then EOF" contract of INV-11. opencode on main has the same stdin path, so the defect predates this PR there. This PR routes Claude through it.
  Smallest fix: Refuse the prompt at the boundary. In `NativeThreadRequest.__post_init__`, for `harness in NATIVE_STDIN_PROMPT_HARNESSES`, try `self.prompt.encode(NATIVE_TEXT_ENCODING)` and raise `ConfigurationError(..., details={"field": "prompt"})` on `UnicodeEncodeError`. Add `("lone-surrogate", "list \ud800 files")` to `PROMPT_CASES` in `test_harness_threads_claude_arguments.py`; the existing `refuse` fixture already asserts that no process started. Doing this for every stdin harness also changes opencode's behaviour, from an orphaned child to a refusal. INV-20 makes that the user's decision; a Claude-only condition is the fallback. As defense in depth, `CliRunner.run` should stop the tree when `_feed_stdin` raises anything else. That is a lib/process behaviour change and is ask-first under §14.
  Spec IDs: INV-5, INV-9, INV-11, AC-8, T-3

R-E2 [Major] [security / failure modes] vidbyte/harnesses/native/hostkit/folders.py:38 (consumed at claude/threads.py:152 with cwd at :121) — A relative user home puts the child's `CLAUDE_CONFIG_DIR` inside the workspace while the SDK prepares a different folder
  Evidence: `folder = Path.home().joinpath(*parts, key)` is never made absolute. `_environment` passes `str(config_dir)` to a child whose `cwd` is the workspace, so the child resolves the relative path against the workspace. Probe `python s4eng/probe_relhome.py` (`HOME=USERPROFILE=relhome`, parent cwd `parentcwd/`):
    `CLAUDE_CONFIG_DIR given to child: relhome\.vidbyte\claude-configs\6b56013a797073ce`
    `child resolves it to: …\s4eng\ws-rel\relhome\.vidbyte\claude-configs\6b56013a797073ce`
    `skills the child sees there: None`
    `folder the SDK prepared (parent cwd): …\s4eng\parentcwd\relhome\.vidbyte\claude-configs\6b56013a797073ce skills: ['write-tests']`
    `config folder lies inside the workspace: True`
  Failure: The trigger is a relative `HOME` (POSIX) or `USERPROFILE` (Windows). That is uncommon, but some hermetic-build and container setups produce it, and `Path.home()` does not check for it. With it set, the caller's skills never reach Claude (INV-14), and Claude writes `.claude.json`, transcripts and memory inside the workspace (INV-13). Worse, `--setting-sources user` reads the "user" `settings.json` from a path inside the workspace. A repository that ships `<relhome>/.vidbyte/claude-configs/<key>/settings.json` can therefore set `env.ANTHROPIC_BASE_URL`, an `apiKeyHelper` or hooks, which is exactly what INV-4 control 3 exists to block. The key is the first 16 hex characters of the SHA-256 of the resolved clone path, which is predictable in CI. The sharpest case is `HOME=.`. There is also a POSIX case, reasoned from the Popen docs and not run on this win32 host. `NativeLauncher` checks `fallback.is_file()` against the parent's cwd, but `subprocess` resolves a relative executable against `cwd=`. So with no `claude` on PATH, a repository that ships `.local/bin/claude` would be executed with the key in its environment. The shared helper also serves Grok (`GROK_HOME`), which had the same gap before this PR.
  Smallest fix: In `NativePrivateFolders.prepare`, inside the existing `try`, treat a non-absolute `Path.home()` as an undeterminable home (raise `RuntimeError`, which the existing branch maps to `launch_failed` with `unknown_detail`). Make `ClaudeThreadRun._fallback` return `None` for a non-absolute home. Add a test that sets `HOME` and `USERPROFILE` to a relative path, expects `claude.launch_failed` and asserts that nothing started. This also changes Grok's behaviour under a broken home, from a silently misplaced home to `launch_failed`, so it needs the user's sign-off against INV-20.
  Spec IDs: INV-4 (control 3), INV-13, INV-14, T-2, T-6, EC-9

R-E3 [Major] [failure modes / observability] vidbyte/harnesses/native/claude/wire.py:41 (before :49) — A run that prints its answer and then fails to exit is reported as `timed_out` with no thread id, which throws away the session it printed
  Evidence: The timeout check runs before `answer = ClaudeWire._answer(outcome.stdout)`, and the `TIMED_OUT` failure is built without `thread_id`. Probe `python s4eng/probe.py print_then_hang`: the stand-in prints a valid success object for session `a65d1958-f397-44c1-9191-fcdf227b0c9e`, flushes, then sleeps past the 3 s timeout. Claude Code can finish its turn, print its one JSON answer and then stay alive, for example because a background shell or a stuck handle keeps the process up. The call then waits the full `timeout_seconds` (up to 4 h), stops the tree, and gives the caller no thread id for a paid run whose transcript and workspace edits exist. INV-6 says the error carries "the session_id of Claude's JSON answer when it is a valid id, even on a failed run". opencode's wire already reads the session before its runner checks for exactly this reason (opencode/wire.py:62 passes `thread_id=session` on timeout). No test covers this: the `hold` mode prints nothing before it holds. Whether 2.1.301 hangs after printing was not measured, but the SDK cannot tell that case apart from a run that never answered.
  Smallest fix: Move the four lines that compute `answer`, `session`, `text` and `newest` (`wire.py:49-52`) above the timeout check, and pass `thread_id=newest` to the `TIMED_OUT` failure (and to `OUTPUT_TOO_LARGE`, where it stays `None`). This adds no `if`, so C901 stays at 8 and the INV-7 code order is unchanged. Add a stand-in mode that prints a success object and then holds, with a test expecting `claude.timed_out` whose `thread_id` is the printed session.
  Spec IDs: INV-6, D-14, EC-14 (assumed "no JSON was printed"), EC-34

VERIFIED CLAIMS:
- INV-4 / AC-6, Windows case-insensitivity (briefing §4): HELD. With `anthropic_auth_token`, `Claude_Config_Dir` and `anthropic_base_url` set in the raw environment block, `_inherited_names()` returned the upper-cased names, and the child saw only the three overlay names (probe_case). On POSIX, lower-case names are different variables, which Claude Code does not read.
- INV-3 / AC-7, redaction on every error path: HELD for `run_failed` from `result` (AC-7 test), from the `errors` list ("bad key <redacted>, again <redacted>"), from bare-exit stderr ("fatal: <redacted> …"), and for `timed_out` stderr (AC-15 test asserts it). `protocol_mismatch` never carries stdout (wire.py:73, :76). A truncated prefix of the key, here its first 20 characters, is not scrubbed, because `register_secret` matches only the exact value. That is by design and was not filed. The test plan says AC-7's stand-in echoes the key on stderr, but the `is_error` branch never reads stderr (wire.py:56-60), so AC-7 proves only the `result` scrub; the stderr scrub is proven by the AC-15 timeout test instead.
- INV-7, non-integer `api_error_status` (briefing §4): HELD. A list or dict gives `run_failed` "completed: boom"; `true` gives `run_failed` "completed (status True): boom". `is_error: "false"` at exit 0 gives `protocol_mismatch`. A status of 401 with no reason or message gives `key_rejected` with `vendor_message` None.
- INV-12 / AC-14 / AC-13: HELD. A continue answered on another lower-case UUID raises `thread_not_found` with the caller's id. A fork answered with its source raises `protocol_mismatch`. An upper-case answer raises `protocol_mismatch` because `_session` returns None (wire.py:106 uses `re.fullmatch`, so a trailing `\n` is refused too; `THREAD_CASES` includes `uuid-newline`).
- INV-5 "every argument is checked before any process starts": DOES NOT HOLD for an unencodable prompt (R-E1). It holds for every case in `PROMPT_CASES`, `THREAD_CASES`, `KEY_CASES` and `MODEL_CASES`.
- INV-13 "never inside the workspace": DOES NOT HOLD under a relative home (R-E2). It holds for the absolute sandbox home that every test uses. Collisions: a 16-hex key is 64 bits, with a birthday bound near 4×10⁹ workspaces. `resolve()` follows symlinks, so a re-pointed symlinked workspace maps to a new folder, which matches EC-7. Not filed.
- INV-9 / INV-10 / INV-11: HELD on the normal paths (timeout plus grandchild, cancel plus grandchild, one start record per call). Not on the R-E1 path.
- INV-15: HELD. `_is_batch` strips trailing dots and spaces and folds case (launcher.py:73). The tests cover `.cmd`, `.bat`, `.CMD`, `"bat."` and `"cmd "`, and the PATH-shim-to-native-install fallthrough. The current-folder decoy test removes `NoDefaultCurrentDirectoryInExePath` and `chdir`s into the workspace, so it can fail in this shell.
- INV-18: HELD for every value the SDK builds. No `bypassPermissions` or `auto` member exists, and the argv tests forbid the flags. A caller's own `claude_command` tail can carry any flag by design, as `grok_command` can, and the tests themselves pass `-u`. Not filed.
- INV-20, Grok switch behaviour-preserving: HELD. The diff deletes `_prepare_home` and passes Grok's five constants to an identical body, and 131 Grok tests pass.
- EC-21, concurrency (briefing §4): CONFIRMED AS ACCEPTED. `NativeSkillFolders.replace` removes and rebuilds `skills/` without a lock (skills.py:34-43). A concurrent call with a different set, or first-use calls with the same set, can wipe `skills/` under a running child or fail `mkdir(parents=True)` as `launch_failed`. This is documented in the likely cause and the README. Not filed.
- S3 report claims: HELD. `ClaudeWire.read` has C901 complexity 8 (ruff fails at a maximum of 7 and passes at 8). The Claude package is 360 lines (NFR-3 ≤ 400). `pyproject.toml` is byte-identical to `b28c3027`. `git grep claude_agent_sdk -- vidbyte` is empty. The 195 Claude tests are green.
