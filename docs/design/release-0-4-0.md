# Release 0.4.0: public skill loader

`vidbyte-sdk` 0.3.0, the latest release on PyPI, keeps the code that turns a skill entry into text private: only `JevAgent`'s skill preload can reach it. vidbyte-cli wants one way to attach skills to all six of its agents, and it may import only names the public contract lists, so it needs a release that exports the loader. This release publishes the public skill loader (#1099) and the 90 PRs on `main` from `v0.3.0` to `82b46c85`, the `main` that PR last merged: 7 features, 82 fixes, and 1 chore. The version is 0.4.0 and not 0.3.1, because #1027 removes a keyword from 8 root exports and changes where default text calls go, and the README says that minor versions carry API changes while the SDK is in alpha. #1179 set `main`'s version literals to 0.3.1, but 0.3.1 was never tagged or published, so 0.4.0 replaces it. No root export is removed.

What 0.4.0 changes, from `git log --first-parent v0.3.0..82b46c85` plus #1099:

- **Public skill loader (#1099), the headline.** `SkillLoader`, `SkillResolution`, and `ConfigurationError` become root exports, so a program that never builds a `JevAgent` can resolve all six #904 skill sources: inline text, local folders, skills.sh, GitHub, Anthropic, and OpenAI. `SkillLoader(entries)` takes a tuple or a list of skill entries and `SkillDocument`s, and raises `ConfigurationError` before any I/O when the argument is text or not an `Iterable`, holds something other than an entry or a document, or repeats a name. `await loader.load()` returns one `SkillResolution` per entry, in input order; an entry that cannot load comes back as a `reason` and a `detail` instead of an exception. `JevAgent` is unchanged.
- **Breaking: provider keys (#1027).** `api_key=` is removed from 11 signatures on 8 root exports: the constructors of `Agent`, `BaseAgent`, `AggregateAgent`, `AgentRoleSettings`, `AgentRunnerConfig` (where it was the first positional field), `JevAgentSettings`, and `JevRunBriefSettings`, plus `Agent.restore`, `BaseAgent.restore`, `Session.resume`, and `Session.fork_from`. All 11 take `api_keys=`, an unordered list of provider keys matched to providers by key format, and all but `AgentRunnerConfig` and `JevRunBriefSettings` also take `vidbyte_api_key=`. Passing `api_key=` to them raises `TypeError`. The skill entries and output connectors keep their own `api_key=`, and `GitHubSkill` keeps `token=`.
- **Breaking default: text calls go through the Vidbyte gateway (#1027).** `Agent`, `BaseAgent`, `AggregateAgent`, `AgentRunnerConfig`, and `JevAgentSettings` default to `model_mode=TextModelMode.AUTO`, which sends every text call through the Vidbyte gateway and needs `VIDBYTE_API_KEY` or `vidbyte_api_key=`; when the call's provider has one of the caller's keys, the gateway relays it so the provider bills the caller. With only a provider key such as `OPENAI_API_KEY`, the first text call fails before any request with `ConfigurationError: Missing Vidbyte API key …`, which `run()` raises as the cause of an `AgentExecutionError`. `TextModelMode.DIRECT`, exported from the root and from `vidbyte.lib.enums`, calls the provider directly with the caller's own key.
- **Working Principles preset (#1095).** An opt-in system-prompt preset that every agent a run starts inherits: the root enum `SystemPromptPreset`, set through `system_prompt_presets=` on `Agent`, `BaseAgent`, and `JevAgentSettings`.
- **Harness threads (#1036).** Nine async functions in `vidbyte.harnesses.native` run, continue, and fork Grok Build, opencode, and Muse Code threads with the caller's own API key. `FailureCode` gains 28 members. #1036 adds no root name; #1179 below does.
- **Native threads from the root (#1179).** The nine thread functions and the eight configs, enums, result, and error that go with them become root exports, 17 names in all, so vidbyte-cli can call them without a deep import. The functions load the first time a caller names one, so a plain `import vidbyte` still leaves `vidbyte.harnesses.native` unloaded.
- **InfiniteMemoryAgent (#1084).** A prebuilt agent for one long task that runs each step as a fresh generator and verifier pair, shares a capped file workspace across them, and resumes an interrupted run from its journal. It adds 4 root exports: `InfiniteMemoryAgent`, `InfiniteMemoryAgentSettings`, `InfiniteWorkspaceSettings`, and `InfiniteMemoryPreset`.
- **CodexHost (#1055).** One host per Codex app-server process, with agent tools, thread helpers, and skill functions, exported from `vidbyte.harnesses.native.codex` and not the root.
- **Jev read-only intent (#1005).** The opt-in preset `JevPreflightPreset.READ_ONLY` recognizes a request for an assessment rather than a change, and then limits every agent in the run to `SAFE` and `READ` tools.
- **Fixes.** 82 fixes. 15 came before `0754e01f`, #1086 to #1094, #1096 to #1098, and #1100 to #1102: compaction (6), context (4), and one each in providers, agents, sessions, Jev, and algorithms. The sessions fix (#1093) adds an `algorithm=` keyword to `Agent.restore`, `BaseAgent.restore`, `Session.resume`, and `Session.fork_from`, so a custom context-window algorithm survives a resume or a fork. The other 67, #1103 to #1178, are led by compaction (15), algorithms (11), runtime (9), Codex (7), and multi-agent (6). Among them is #1104, which carries #1027's `api_keys` and `model_mode` into child runners.
- **Later changes on `main`.** The tag is cut on `main` after this PR merges, so anything merged there after `82b46c85` ships too; `git log --first-parent 82b46c85..v0.4.0` lists it beside #1099. Among them, #1190 makes `AgentLoopSettings`, `PermissionPolicy`, `TextModelMode`, and `JevDynamicComputeOption` root exports, 4 names, so vidbyte-cli can set `JevAgent`'s loop limits, allow write and execute tools, choose the text-model mode, and name compute options without a deep import; the four classes and their defaults are unchanged. The loop spend cap (#1192) adds `AgentLoopSettings.max_spend_usd`, an optional USD cap the shared agent loop checks against the run's live priced usage before every model call, tool call, finish attempt, and compute checkpoint; a run it stops ends with the new stop reason `AgentStopReason.MAX_SPEND`, which sessions report as the existing `resource.exhausted`, and `UsageRollup` gains the read-only `cost_measured`. No root name, `FailureCode` member, or default changes, so the contract still lists 733 exports. The reasoning effort (#1193) adds the root enum `ReasoningEffort` (`none`, `minimal`, `low`, `medium`, `high`, `xhigh`) and an optional `reasoning_effort` on `BaseAgent` and `JevAgentSettings`, which each provider adapter sends in that provider's documented wire form on `TextModelMode.DIRECT` calls; construction refuses it with `ConfigurationError` in a gateway mode, beside `thinking_config`, or for a model and value with no documented form, and nothing is sent when it is unset. The same change makes `DecisionModelConfig` and `DecisionModelMode` root names, so the contract lists 736 exports; no `FailureCode` member or default changes. The Jev 1.14 pricing fix (#1194) must be on `main` before the tag: TypeSafe moved `jev-latest` to `jev-1.14.0` on 2026-10-14, the pricebook priced only `jev-1.13`, and every `JevAgent` run that asked Jev then raised `UsageAccountingError` after its decision call was billed. It adds the `jev-1.14` row ($0.042 per million input tokens), moves `PRICING_AS_OF` to 2026-10-25, and has `DecisionModelRunner` pass the requested model to the run's ledger, so a later TypeSafe release the pricebook lacks is priced as the requested model, such as `jev-latest`; a request for an unpriced model still fails closed. It adds no root name, so the contract still lists 736 exports, but the backend's pricebook identity, `vidbyte-sdk-models-{PRICING_AS_OF}`, changes when it upgrades from 0.3.0.

Every literal that names the version moves together, as in the 0.2.0, 0.2.1, and 0.3.0 releases: `pyproject.toml`, `vidbyte/__init__.py`, the CLI fallback, the MCP server default, the MCP `clientInfo`, `README.md`, `llms.txt`, the bug template, and the regenerated `contracts/sdk-public-api.json`. The contract now lists 736 exports, against 639 at `v0.3.0`: 97 added and none removed, 3 from #1099, 4 from #1084, 17 from #1179, 11 from #1189, 3 from #1159, 51 from #1147, 4 from #1190, `SystemPromptPreset` from #1095, and 3 from #1193. It records names only, so #1027's removed parameters do not show there. No dependency changes, and the `codex` extra keeps `openai-codex>=0.162.1,<0.163.0`. Do not tag until the Meta key fix, #1184, is on `main`: on 2026-10-18, `main`'s Meta key rule still matched only the legacy `LLM|` shape, and #1184 records how a Meta key issued in the current `LLM_` shape could otherwise be sent to another vendor. Before tagging, vidbyte-cli's checks run against a locally built 0.4.0 wheel, including #1027's gateway routing against its agents, because the CLI's current `<0.4` pin does not admit this release; vidbyte-cli then pins `vidbyte-sdk[codex]>=0.4.0,<0.5`. To release after merge, push the tag `v0.4.0` on the merge commit and dispatch `publish.yml` on that tag. The workflow checks that the tag matches the package version, reruns CI, and publishes through the `pypi` environment.
