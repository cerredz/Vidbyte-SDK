# Release 0.4.0: public skill loader

`vidbyte-sdk` 0.3.0, the latest release on PyPI, keeps the code that turns a skill entry into text private: only `JevAgent`'s skill preload can reach it. vidbyte-cli wants one way to attach skills to all six of its agents, and it may import only names the public contract lists, so it needs a release that exports the loader. This release publishes the public skill loader (#1099) and the 18 PRs on `main` from `v0.3.0` to `0754e01f`, the `main` that PR last merged: 3 features and 15 fixes. The version is 0.4.0 and not 0.3.1, because #1027 removes a keyword from 8 root exports and changes where default text calls go, and the README says that minor versions carry API changes while the SDK is in alpha. No root export is removed.

What 0.4.0 changes, from `git log --first-parent v0.3.0..0754e01f` plus #1099:

- **Public skill loader (#1099), the headline.** `SkillLoader`, `SkillResolution`, and `ConfigurationError` become root exports, so a program that never builds a `JevAgent` can resolve all six #904 skill sources: inline text, local folders, skills.sh, GitHub, Anthropic, and OpenAI. `SkillLoader(entries)` takes a tuple or a list of skill entries and `SkillDocument`s, and raises `ConfigurationError` before any I/O when the argument is text or not an `Iterable`, holds something other than an entry or a document, or repeats a name. `await loader.load()` returns one `SkillResolution` per entry, in input order; an entry that cannot load comes back as a `reason` and a `detail` instead of an exception. `JevAgent` is unchanged.
- **Breaking: provider keys (#1027).** `api_key=` is removed from 11 signatures on 8 root exports: the constructors of `Agent`, `BaseAgent`, `AggregateAgent`, `AgentRoleSettings`, `AgentRunnerConfig` (where it was the first positional field), `JevAgentSettings`, and `JevRunBriefSettings`, plus `Agent.restore`, `BaseAgent.restore`, `Session.resume`, and `Session.fork_from`. All 11 take `api_keys=`, an unordered list of provider keys matched to providers by key format, and all but `AgentRunnerConfig` and `JevRunBriefSettings` also take `vidbyte_api_key=`. Passing `api_key=` to them raises `TypeError`. The skill entries and output connectors keep their own `api_key=`, and `GitHubSkill` keeps `token=`.
- **Breaking default: text calls go through the Vidbyte gateway (#1027).** `Agent`, `BaseAgent`, `AggregateAgent`, `AgentRunnerConfig`, and `JevAgentSettings` default to `model_mode=TextModelMode.AUTO`, which sends every text call through the Vidbyte gateway and needs `VIDBYTE_API_KEY` or `vidbyte_api_key=`; when the call's provider has one of the caller's keys, the gateway relays it so the provider bills the caller. With only a provider key such as `OPENAI_API_KEY`, the first text call fails before any request with `ConfigurationError: Missing Vidbyte API key …`, which `run()` raises as the cause of an `AgentExecutionError`. `TextModelMode.DIRECT`, exported from `vidbyte.lib.enums` and not the root, calls the provider directly with the caller's own key.
- **Working Principles preset (#1095).** An opt-in system-prompt preset that every agent a run starts inherits: the root enum `SystemPromptPreset`, set through `system_prompt_presets=` on `Agent`, `BaseAgent`, and `JevAgentSettings`.
- **Harness threads (#1036).** Nine async functions in `vidbyte.harnesses.native` run, continue, and fork Grok Build, opencode, and Muse Code threads with the caller's own API key. `FailureCode` gains 28 members, and no root name is added.
- **Fixes.** 15 fixes, #1086 to #1094, #1096 to #1098, and #1100 to #1102: compaction (6), context (4), and one each in providers, agents, sessions, Jev, and algorithms. The sessions fix (#1093) adds an `algorithm=` keyword to `Agent.restore`, `BaseAgent.restore`, `Session.resume`, and `Session.fork_from`, so a custom context-window algorithm survives a resume or a fork.
- **Later fixes on `main`.** The tag is cut on `main` after this PR merges, so fixes merged there after `0754e01f` ship too; `git log --first-parent 0754e01f..v0.4.0` lists them beside #1099. Among them is #1104, which carries #1027's `api_keys` and `model_mode` into child runners.

Every literal that names the version moves together, as in the 0.2.0, 0.2.1, and 0.3.0 releases: `pyproject.toml`, `vidbyte/__init__.py`, the CLI fallback, the MCP server default, the MCP `clientInfo`, `README.md`, `llms.txt`, the bug template, and the regenerated `contracts/sdk-public-api.json`. The contract now lists 643 exports, against 639 at `v0.3.0`: 4 added and none removed. It records names only, so #1027's removed parameters do not show there. No dependency changes, and the `codex` extra keeps `openai-codex>=0.162.1,<0.163.0`. Before tagging, vidbyte-cli's checks run against a locally built 0.4.0 wheel, including #1027's gateway routing against its agents, because the CLI's current `<0.4` pin does not admit this release; vidbyte-cli then pins `vidbyte-sdk[codex]>=0.4.0,<0.5`. To release after merge, push the tag `v0.4.0` on the merge commit and dispatch `publish.yml` on that tag. The workflow checks that the tag matches the package version, reruns CI, and publishes through the `pypi` environment.
