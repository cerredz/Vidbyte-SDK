# Release 0.3.0: output connectors

`vidbyte-sdk` 0.2.1, the latest release on PyPI, predates the output connectors in `vidbyte/lib/outputs/` (#882). vidbyte-cli PR #166 adds `--send-to`, which sends an agent's finished reply to Slack, email, an issue tracker, and so on through those connectors. A CLI installed from PyPI resolves the SDK from PyPI, so until a release with the connectors exists there, `--send-to` cannot work for those users. This release publishes everything on `main` since `v0.2.1`: 380 commits, of which 11 are features and 365 are fixes. The version is 0.3.0 and not 0.2.2, because `main` adds 46 root exports, and the README says that minor versions carry API changes while the SDK is in alpha. No root export is removed. The `vidbyte-sdk coding run` command was added (#747) and removed (#761) inside this range, so it never shipped.

What 0.3.0 adds, from `git log v0.2.1..HEAD`:

- **Output connectors (#882), the headline.** An agent can send each finished reply to 16 destinations: Slack, Discord, Microsoft Teams, Google Chat, Telegram, email over SMTP, GitHub Issues, the GitHub Actions job summary, GitLab, Linear, Jira Cloud, Confluence Cloud, Notion, Typefully drafts, HubSpot tasks, and any HTTPS webhook. The developer passes connectors as `outputs=[...]` to `Agent`, `BaseAgent`, or `CodingAgent`, or as `JevAgentSettings.outputs`. Each connector reads one static key from its argument or its environment variable. Plain SDK code sends the reply after the reply passes its schema check, so the model never sees a key or picks a target. Each destination gets one receipt in `reply.metadata["deliveries"]`, and any failed send raises `OutputDeliveryError` after every send has finished. This adds 24 exports: the 16 connector classes, plus `OutputConnector`, `OutputDispatcher`, `OutputContent`, `OutputDestination`, `DeliveryReceipt`, `DeliveryStatus`, `OutputDeliveryError`, and `TypefullyPlatform`.
- **`CodingAgent` (#747).** A `BaseAgent` with bash, file, search, and web-fetch tools: `CodingAgent`, `CodingAgentSettings`, and `CodingAgentTools`. Later changes add `readonly_paths` (#768), `max_rewrite_lines` (#770), `verify_command` (#772), and loading `AGENTS.md` through a shared coding context window (#769).
- **JevAgent skills (#698, #904).** JevAgent preloads text skills scored for relevance (#698), and loads skills from inline text, local folders, skills.sh, GitHub, Anthropic, and OpenAI (#904). This adds 14 exports, among them `InlineSkill`, `LocalSkill`, `SkillsShSkill`, `GitHubSkill`, `AnthropicSkill`, `OpenAISkill`, `JevAlignmentSettings`, and `JevSkillsOutcome`.
- **Jev bulk work (#702).** A `BULK_WORK` preset runs bounded workers, each a fresh agent: `JevBulkHandoff`, `JevBulkSettings`, and `JevBulkWorkResult`.
- **Codex.** Output contracts translate to Codex turns (#420), which adds `CodexContractOutcome` and `CodexContractResult`, and Codex agents compose into pipelines (#421).
- **Other features.** A Vidbyte-managed mode sends text calls through `POST /api/v1/models/generate` (#759). The model catalog and pricebook are refreshed for October 2026 (#856). `write_text` and `replace_text` show the diff of what they changed (#767).
- **Fixes.** 365 fixes. Most are in tools (79), agents (51), sessions (30), providers (24), evals (24), and middleware (18).

Every literal that names the version moves together, as in the 0.2.0 and 0.2.1 releases: `pyproject.toml`, `vidbyte/__init__.py`, the CLI fallback, the MCP server default, the MCP `clientInfo`, `README.md`, `llms.txt`, the bug template, and the regenerated `contracts/sdk-public-api.json`. The contract now lists 639 exports, against 593 at `v0.2.1`: 46 added and none removed. No dependency changes, and the `codex` extra keeps `openai-codex>=0.162.1,<0.163.0`. Before tagging, vidbyte-cli's full gate and PR #166's feature scripts run against the locally built 0.3.0 wheel through `PIP_FIND_LINKS`. To release after merge, push the tag `v0.3.0` on the merge commit and dispatch `publish.yml` on that tag. The workflow validates the tag, reruns CI, and waits for approval on the `pypi` environment before uploading. vidbyte-cli then raises its floor to `vidbyte-sdk[codex]>=0.3.0,<0.4`, so a fresh install always gets the connectors.
