# Release 0.2.1: openai-codex 0.162

`vidbyte-sdk` 0.2.0 pins the `codex` extra to `openai-codex>=0.147.0,<0.148.0`. In openai-codex 0.147, `AsyncTurnHandle.stream()` reads turn notifications by awaiting `asyncio.to_thread(next_turn_notification)`, and that worker blocks in `queue.get()`. When a turn is cancelled mid-stream, the stream's `finally` unregisters the queue without waking the worker. `fail_all` on client close then cannot reach it, and `asyncio.run()` hangs forever in `shutdown_default_executor`. vidbyte-cli hit this on 2026-10-10. A suggestion run cancels its turn whenever a stop-and-message tool fires, and an `asyncio.timeout` cancels the same way. The run computed its result and then never exited, and MCP jobs stayed `running`. No caller-side workaround exists, because `concurrent.futures` joins every executor thread at exit.

openai-codex 0.154.0, the first release after 0.147.0, replaced the per-turn queue with a `_TurnSubscription`. Its `close()` calls `notify_all()`, so `unregister_turn` wakes a blocked reader with `TransportClosedError`. This release moves the pin to `openai-codex>=0.162.1,<0.163.0`, the current release, which keeps that fix. The pin stays one minor wide, as before, because the adapter reaches private client attributes. The SDK version becomes 0.2.1, and every literal that names it moves together, as in the 0.2.0 release: `pyproject.toml`, `vidbyte/__init__.py`, the CLI fallback, the MCP server default, the MCP `clientInfo`, `README.md`, `llms.txt`, the bug template, and the regenerated `contracts/sdk-public-api.json`. `CodexClientSettings.client_version` mirrors `CodexConfig`'s default, which is now `0.162.1`, and the docstrings and the codex README that named 0.147 now name 0.162.

Compatibility was checked against the installed 0.162.1 in four ways. The full test suite passes with it, 2736 passed and 7 skipped, the same as on 0.147.0; the skips are optional tracing and tokenizer dependencies. The parameters of every method the adapter calls only gained optional names: `include_turns` on `thread_resume` and `thread_fork`, and `source` and `turn_service_tier` on `AsyncThread.run` and `turn`. Every value of the seven Codex enums converts into openai-codex's own type. The new client's minimum-runtime check, Codex CLI 0.151.0 or newer, fires only when a call sends `toolOutput`, `turnTrigger`, `serviceTierForTurn`, or `excludeTurns`, and the adapter sends none of them, so older Codex binaries keep working.

`tests/test_codex_tools.py` gains `test_cancelled_turn_releases_its_waiting_reader` in the existing `CodexSdkContractTests`. It blocks a reader on a registered turn, unregisters the turn, and expects the reader to exit with `TransportClosedError` within two seconds. It fails on 0.147.0 and passes on 0.154.0 and 0.162.1. Like the other contract tests, it skips when the `codex` extra is absent, and `ci.yml` installs only `.[dev]`. To release after merge, push the tag `v0.2.1` on the merge commit and dispatch `publish.yml` on that tag. The workflow validates the tag, reruns CI, and waits for approval on the `pypi` environment before uploading. vidbyte-cli then raises its floor to `vidbyte-sdk[codex]>=0.2.1`, so a fresh install cannot resolve the version that hangs.
