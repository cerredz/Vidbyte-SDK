# Adding Prompts

Use this guide when adding prompt assets to the Vidbyte SDK.

Prompts in this SDK are plain repository text assets. They are not tools, do not
contain tool-call schemas, and are not overridden through file paths at runtime.

## Prompt Assets

- Add prompt files under `vidbyte/prompts/prompts/`.
- Use one JSON file per prompt family.
- Each JSON file must include `name`, `description`, `key`, and `prompts`.
- Use snake_case for the family `key` and every prompt key inside `prompts`.
- Each prompt value should be a coherent sentence block, not an anonymous inline string.
- Do not include secrets, credentials, customer data, tool-call payloads, or provider-specific function-calling JSON.

## Enum And Import Flow

- Add one enum member per leaf prompt in `vidbyte/lib/enums/prompts.py`.
- The enum value must be `<family_key>.<prompt_key>`, for example `chain_of_thought.reason_prompt`.
- The enum member name should be uppercase snake case, for example `CHAIN_OF_THOUGHT_REASON_PROMPT`.
- The direct import name is generated by replacing the enum value's dot with an underscore, for example `chain_of_thought_reason_prompt`.
- Confirm users can access the prompt with `Prompts().get(Prompt.CHAIN_OF_THOUGHT_REASON_PROMPT)`.
- Confirm users can import the text directly with `from vidbyte.prompts import chain_of_thought_reason_prompt`.

## Strategy Flow

- Strategy prompt classes should expose `export()` by reading from `vidbyte.prompts.Prompts`.
- If a strategy needs all prompts in a family, use `Prompts().family("<family_key>")`.
- Do not hardcode strategy prompt bodies directly inside strategy classes.
- Keep prompt dictionaries inspectable so SDK users can reuse and audit them.
- Runtime prompt override and file-path replacement are intentionally unsupported.

## Verification

- Run `python -m compileall vidbyte`.
- Run `python -m unittest discover -s tests`.
- Add or update tests for enum lookup, direct imports, descriptions, and any strategy that consumes the prompt family.
